## 迁移范围

公开站点、旧 /v1 API、静态资源由迁入的 aiohttp 平台服务负责；/api/v1 交给 FastAPI；大文件下载交给镜像进程。由 Nginx 按路径直接分流，避免自写 ASGI/aiohttp 协议桥和 Python 二次文件代理。内部控制接口不公开。提供可独立运行的 CLI 与统一进程启动入口，子进程异常时清理其余进程。

## 数据库设计与过渡边界

依赖事实/作业继续 SQLAlchemy/Alembic + PostgreSQL，SQLite 仅本地测试。原源站 Store 深度依赖 aiosqlite、FTS5 trigram、SQLite upsert 和现有持久化格式；本次完整保留在独立 data/platform 下，禁止把它接到新事实库或声称已支持 PostgreSQL。镜像副本账本和配置继续由镜像进程拥有，避免跨进程同时写同一账本。

不直接把 SQL 字符串替换为 PostgreSQL：后续按目录/原文、译文/分段、任务/额度、身份/统计逐领域迁移，通过离线导出、计数/摘要核验、冻结写入、恢复演练后切换；搜索索引可重建。依赖事实与源站资源通过 provider/project_id/file_id/内容摘要显式关联。两套持久队列不合并状态枚举，完成平台数据层迁移前不承诺多平台写入副本。

## 本次重设计

1. 去掉隐式 G 盘路径、第三方模型中转与 CurseForge 代理默认值。默认无模型 Key、不付费调用；只使用明确环境/站内配置。
2. 一个 Vue/npm 工程构建全部页面，旧控制器暂由页面生命周期 scope 管理；所有普通 HTTP 走共享 Axios 兼容层，保留响应/取消语义；联邦 SSE 流仅保留必要的原生流通道。
3. 内容、作业、运维、接入、设置分别归属；云迁移属于作业，来源质量属于监控，存储/路由策略属于设置。依赖工作台和旧页面通过真实导航连接，不把所有表单塞进总览。
4. 构建产物隔离到忽略目录；不能将几百份过期哈希 chunk 作为源码搬入。原始资源和页面源码保留来源清单。
5. 同源管理员会话可进入依赖工作台；校验仅访问固定内部平台地址、不接受用户指定认证 URL，不信任客户端传入的“已登录”。Cookie 写操作校验 Origin，失败关闭权限。
6. 扩展原有自动方法索引和 CI，运行迁入的原测试；迁入页面必须实际浏览器打开、核对文字/布局并查看截图，未测能力明确记录。
