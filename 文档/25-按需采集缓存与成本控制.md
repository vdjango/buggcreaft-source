# 按需采集缓存与成本控制

> 本页先定义本轮实施契约，完成状态及实际测试结果记录第 13 号。聚合/全文/语义搜索继续按第 22–24 号独立推进，不以本轮采集优化冒充搜索交付。

## 范围与复用

按用户确认的成本边界，先落实按需、去重、缓存、限额和小批热门预热；不全量遍历互联网或历史文件，不人工补关系图。复用现有 Repository 队列/租约、ArtifactStore 下载/CAS、Collector/ArchiveReader/parsers、SQLAlchemy upsert 与 FastAPI；不引入 Redis、第二套调度框架或下载器。

## 采集与缓存契约

1. 请求增加 purpose=on_demand/warmup，默认按需。按需优先；已有预热排队项被按需请求命中时提升优先级。来源元数据、正文不能参与依赖事实生成。
2. 请求指纹包含 parser_version。SHA-256/SHA-512 请求按算法+摘要合并，可跨 URL；无摘要及 SHA-1 请求把完整 URL 和摘要条件纳入指纹，不擅自删除签名参数。指纹在数据库保存 SHA-256，不在 API 暴露 URL。
3. 同一指纹的 queued/running 任务共享 ID；共享任务取消影响所有等待该任务的调用者。它是管理采集任务，尚不是多租户订阅系统。相同强摘要的已成功任务可直接返回；失败/取消允许新任务。
4. 只有本地完整扫描过的 artifact/scan，以及成功下载核验后保存的 SHA-512→SHA-256 映射可用于完成态缓存。来源 ID、URL、SHA-1、介绍或客户端自报“已扫描”不能作为完成态命中依据。
5. 即使 URL 不同或无摘要，下载得到相同 SHA-256 后也复用同 parser_version 的不可变 scan，跳过重复解压/解析。partial/unsupported 仍保持原状态，不能缓存成完整零依赖。
6. 解析器升级只命中当前版本 scan；已有已核验强摘要可定位本地 CAS，流式重验本地字节后重扫，不必重新联网。缺失文件回退下载，损坏 CAS 明确失败，不静默覆盖证据。已持久化历史扫描可独立查询，存储完整性由运维核验，不能声称每次查询都重新验证所有证据文件。
7. 原始任务记录保留首次来源；合并请求不会把新来源冒充首次来源。后续逐来源 observations 仍属独立阶段。

## 队列与成本限制

- 新增数据库短事务闸门，使用 SQLAlchemy upsert+单行更新串行化准入/领取；事务中无网络/解压。跨 API/worker 进程共享，SQLite 仍限单 worker。已有队列、租约/token 和取消语义继续复用。
- 默认最多 1,000 个 queued/running 待处理任务；重复在途/完成态缓存命中不占新名额。满队列 API 返回 429 和 Retry-After，CLI 非零退出。
- 默认最多 4 个 running 任务，全局生效；过期租约先回收，不把失联 worker 永久占作有效运行者。每个 worker 仍只运行一个任务。
- 默认每个 UTC 自然日预留下载预算 20 GiB。每次实际网络传输前在数据库原子预留一个单文件上限（默认 256 MiB）；失败/崩溃不退款，额度是保守上界而非实际流量统计。无网络缓存不消耗额度；新租约重试需重新预留。每条任务当前领取 token 的预留幂等。预算不足任务明确失败，人工在预算恢复后重试，不忙循环。
- 每次下载/本地导入前以及写入期间检查最低可用磁盘（默认 512 MiB），低于阈值清理 .part 并失败。多进程磁盘竞争仍需部署卷配额；不是完整存储容量/GC 替代品。
- 单文件、超时、元数据、总解压、层数预算沿用既有设置。配置由显式环境读取并校验正数；max_depth 可为 0 表示不递归，不能把 0 当无限。
- manifest 每批默认最多 100 行，设置 --limit 明确边界；超过边界明确非零退出，已排队行保留，重跑通过指纹合并。预热通过 --warmup 显式选择，不自动追溯历史。批量本地导入复用已扫描结果。

## 数据迁移与接口

新增 collection_keys（指纹→最近任务）、collection_gate（准入互斥行）、download_budgets（UTC 日期和保守预留字节）、artifact_hashes（已核验 SHA-512→SHA-256）；Job 增加 parser_version、priority、cache_hit、download_reservation_token。索引覆盖 state/priority/created_at 与过期租约；不能每次准入扫描历史 JSON。

POST collections 仍接收 CollectRequest，缓存完成时 200、待处理时 202。JobView 明确 parser_version、priority 和 cache_hit（该任务是否跳过了解压/解析或直接从完成态缓存生成），不表示作者身份认证。队列满 429，非法来源仍 422，即使命中缓存也先校验来源；预算/磁盘错误进入任务失败记录。重试同样受准入约束。

## 验收

需要证明相同在途提交只有一个任务、相同强摘要完成态无第二次 HTTP/解析、无摘要 URL 换内容不会被旧缓存遮蔽、SHA-1 不跨 URL 命中完成态、解析器版本隔离、本地旧制品重扫不联网、旧 token 不能记账/提交、并发预算不超限、满队列缓存仍可用、按需优先、磁盘低水位失败清理和批次边界。PostgreSQL 多线程准入/领取/预算需真实服务验证，SQLite 单测不能替代。

性能记录应包含 HTTP 次数、解析次数和已预留下载字节；命中延迟测 P50/P95，但单机夹具时间不构成线上 QPS 承诺。业务代码修改后运行相关测试、Ruff、索引和前端构建（若改 UI）；全部新增类/方法同步第 12、18 号。
