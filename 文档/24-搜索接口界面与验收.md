# 搜索接口界面与验收

> 下文为目标契约与质量门槛。当前公共全文/语义/相似及管理作业/状态已实现，真实 OpenAPI、模型、字段、多节点和逐图验收见 [第 32 号](32-搜索实现与多节点契约.md)，第 12、18、28 号同步真实代码。未实现的参数/代次切换/性能门槛不视为通过。

## 公共 API 草案

| 方法/路径 | 输入 | 输出与边界 |
| --- | --- | --- |
| GET /api/v1/search | q、mode(lexical/semantic/hybrid，默认 hybrid)、types、sources、mc_version、loader、side、language、limit、cursor | 项目列表、来源、真实命中片段、模式/覆盖/代次/降级信息 |
| GET /api/v1/projects/{id}/similar | mc_version、loader、side、limit、cursor | 语义相似项目，排除自身及确认同源副本；不等于可替换/兼容 |
| GET /api/v1/search/capabilities | 无 | 实际可用的全文/语义/语言/资源类型，模型服务可用性和索引水位 |
| POST /api/v1/admin/search/rebuilds | 目标配置版本、资源范围 | 202 持久重建任务；管理权限，不在请求里计算向量 |
| GET /api/v1/admin/search/rebuilds/{id} | 任务 ID | 按真实项目/块计数的状态、失败、覆盖率和水位 |

`q` 初始上限 200 个 Unicode 字符、分词后最多 32 个有效查询项；limit 默认 20、最大 50；每路候选、推理输入和总请求预算都独立受限。空 q 走确定性目录浏览，按发布时间和 ID 排序，不调用 embedding；没有语义模型时 capabilities 必须反映实际能力。

来源 ID/slug/mod ID 属精确搜索输入类型，普通字符串只按匹配策略查询，不接受用户任意 URL 触发抓取。若以后支持粘贴来源链接，只解析受控 provider+ID，不将它交给通用下载器。

公共只读 API 是单独的限流/缓存权限面，不能放开目前带管理令牌的采集路由。管理重建具备独立鉴权、审计和范围限制。搜索路由不在 API 线程内下载正文、翻译或离线生成文档向量；实时 query embedding 经有界并发的独立推理端口调用。

## 筛选契约

- 同时指定 `mc_version=1.21.1` 与 `loader=fabric` 时，必须存在同一个公开版本/文件同时满足两者。不能用文件 A 的 MC 版本和文件 B 的加载器拼出虚假兼容；适用的运行侧也在该文件范围内核对。
- 未提供版本筛选，按项目检索并展示候选支持范围；已提供筛选但元数据缺失，默认不当作满足条件。资源包/光影等不适用加载器的资源类型单独定义 N/A，不能假装是 Fabric 模组。
- 上游版本标签是候选证据，返回 `compatibility_basis=source_metadata`；若已绑定真实 scan，可另外列 `artifact_declared` 与扫描完整性。任何一项都不宣称已经完成全局依赖求解或游戏运行测试。
- 原文与可发布译文共同召回；language 控制优先展示语言，返回每个命中段落实际语言和是否为译文，不制造不存在的中文结果。

## 响应字段草案

顶层：`requested_mode`、`effective_mode`、`degraded`、`degradation_reason`、`index_generation`、`config_revision`、`catalog_watermark`、`indexed_at`、`coverage`、`items`、`next_cursor`、`has_more`、`candidate_window_exhausted`。混合召回的候选数不是全站精确总数，不返回虚假的 `total_count`。

每个项目：`project_id`、`resource_type`、`project_title`、可空 `translated_title`、`sources`、`match_types`、`snippets`、`candidate_release_refs`、`compatibility_basis`、`dependency_scan_status`、`document_revision`。包内名字只在有关联制品时以独立 `artifact_names` 给出，不能用项目名字填充。

每个 snippet：`document_id`、`source_ref`、`field`、`language`、`is_translation`、`review_state`、`source_hash`、`text`、可空 `highlights[{start,end}]`。偏移约定为片段内 Unicode code point、左闭右开；前端转换为字符数组再切分，不能拿 Python 偏移直接当 JavaScript UTF-16 单元偏移。语义相关的段落允许没有关键词高亮，不能生成正文里不存在的引文。

内部相关度和余弦分数可用于调试，不作为“可信度/兼容率/安全率”展示。正文写了某前置，只能在命中片段里显示作者原话，依赖清单仍链接具体 SHA-256 的真实 scan。

## 稳定分页与缓存

首请求在有界候选窗口内形成稳定项目列表，短期保存检索会话（初始 TTL 5 分钟、最大 1,000 个项目引用，按实际候选数存）。游标签名绑定 session、query/filter hash、权限、语言、检索配置、索引代次和页偏移；不能只用 `OFFSET` 对变化中的 ANN 排名翻页。

换词、换筛选、索引切代或会话过期需要重新搜索；语义相关度分页只保证该候选窗口内的稳定性。到窗口边界时 `candidate_window_exhausted=true`，提示细化查询，不伪装已经遍历全站。每页读取重新核对可见性和当前投影；被下架/修订的条目跳过并从会话后续候选补足，无法补足时允许少于 limit，不返回撤回文本。

初版错误：422 非法参数/超限；400 `invalid_cursor`；409 `search_generation_changed`；410 `search_session_expired`；429 限流/推理并发预算；503 `search_unavailable`/`semantic_unavailable`。混合模式的词法可用而语义超时，可 200 返回 `effective_mode=lexical`、`degraded=true` 及原因；semantic 专用请求不可悄悄降级，全文也不可用则 503。取消请求应传播推理调用的超时/断开信号，不留无界后台请求。

## Vue 页面与共享职责草案

资源搜索独立页面，由 Vue Router 在真正新增多页时接入；共享状态再评估 Pinia。数据请求扩展现有 `frontend/src/api.ts` 的唯一请求入口，不在卡片里各写 fetch。

| 拟建组件/职责 | 复用与输入 | 真实状态 |
| --- | --- | --- |
| 搜索栏 | 查询、模式、受控联想词；300 ms 防抖+提交，取消旧请求/序号拒绝迟到结果 | 空输入、请求中、无结果、失败 |
| 筛选栏 | 类型/来源/MC/加载器/运行侧/语言；URL 保存可分享的非敏感查询状态 | 条件变化清旧游标，筛选不可用明确提示 |
| 项目结果卡 | 一个规范项目、多来源入口、真实原名/译名、命中类型和片段 | 待译、正文未收录、语义降级、依赖待采集分别显示 |
| 命中片段 | 复用文本与高亮渲染器 | 禁止 v-html，不展示任意作者 HTML |
| 相似资源区 | 复用结果卡和筛选参数 | “功能相近”，不显示“可安全替换” |
| 索引管理页 | 服务任务/水位/覆盖/错误/重建查询 | 不用前端计时推算建索引进度 |

面向玩家页面使用“名称匹配”“正文包含”“功能相近”等语言；数据库、模型维度、RRF 只在管理诊断显示。语义服务超时提示“相近含义搜索暂不可用，已显示文字匹配结果”，不能让玩家误以为没有更多语义结果。点击命中进入对应版本/来源正文位置，显示片段的原文/译文来源。

## 实施任务与验收顺序

| 任务 | 交付 | 验收 |
| --- | --- | --- |
| S0 输入复用 | 旧目录/正文/译文版本化适配、增量/删除事件契约、许可标记 | 无凭据也可用固定契约夹具；断页重试不丢项目；正文不能只有简介 |
| S1 数据迁移 | 文档、别名、块、generation/head/outbox 和任务；扩展部署 | 真 PostgreSQL 升级/回填/回滚演练；旧 scan 不变 |
| S2 全文检索 | 中文分词/词表、原文和译文全文、精确/模糊、过滤、片段 | 标题/简介没有词但正文有词必须命中；两字词、ID、语言、同版本过滤通过 |
| S3 语义基线 | 固定 embedding 模型服务、块向量、精确向量检索 | 无字面重合的查询在人工标注集召回；模型断开明确失败/降级 |
| S4 混合与相似 | RRF、去重、相似资源、分页/缓存 | 精确 ID 不被挤走；同源/多语言不刷分；游标和撤回安全 |
| S5 性能与发布 | ANN、推理批量/缓存、监控、前端浏览器测试 | 过滤后的召回对照精确基线，容量/恢复和 UX 实测记录 |

S2 可以在 S3 前提供有价值的正文搜索，但不能在完成 S2 时宣称语义也已交付。每个任务新增的真实方法/类更新第 18 号，模块 I/O、异常、取消、资源所有权更新第 12 号；拟建方法不预写进源码索引。

## 功能与质量测试集

必须覆盖：标题/简介/正文原文、中文译文中段落独有的词；英文/中文别名；两字汉语、未知词、错拼、连字符 ID、简繁与 emoji 偏移；无翻译；撤回译文；完整正文与处理截断；同名不同项目；同源已确认/未确认；正文提“前置”但 JAR 无声明；相似资源排自身；MC/加载器不能跨文件拼接；翻页时下架；过期/篡改游标；embedding 超时、维度/revision 错误；旧索引任务晚提交；重建期间增量/删除不丢失。

语义必须准备人工标注查询集，初始至少 100 条，划分调参集和固定留出集，中文自然语言、跨语言、模糊意图和零相关查询分别统计。标签来自资源真实正文和人工核对，不由同一个 embedding/聊天模型自评。报告 lexical、semantic、hybrid 三路的 recall@20、MRR@10、nDCG@10、零结果率和来源/语言分布；同时报告词法已有能力是否回退。

首轮发布目标（待测、可依据样本调整）：精确项目 ID 在可见且满足过滤时 top1=100%；固定语义留出集 hybrid nDCG@10 相对 lexical 至少提升 5%且各关键子集无明显退化；ANN 对同过滤精确向量基线 recall@20 ≥95%；可见性/同文件过滤隔离测试全部通过。未达到则不按“智能搜索已完成”发布。

性能实验用第 23 号硬件和 10 万项目/实际块数，20 个并发客户端持续 10 分钟，冷/热缓存分别记录；目标全文端到端 P95 ≤200 ms，混合含 query embedding P95 ≤800 ms。模型硬件、文档块数、过滤比例、实测 QPS、P99 和内存单独报告。不是当前性能承诺，也不能只测缓存命中路径。健康状态水位应显示实际索引滞后；常规增量目标 P95 ≤5 分钟，大批翻译/回填单独记录。
