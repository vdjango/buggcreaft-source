# 2026-11-12 节点自动刷新与缓存统计

## 问题和修复

节点列表原来仅在会话种子/认证回调时请求，已登录用户经 SPA 从其他后台页面进入时可能没有触发加载。现在 `admin-nodes.vue` 监听共享认证状态并立即刷新，仍调用原 nodeAccess / roomClientCache store；页面可见时每 10 秒刷新，离开停止定时并中止本页读请求，迟到结果不写状态。显式写操作不复用该读取消令牌。

公开首页旧 `cached_files` 是 URL 映射条数，旧 `cached_bytes` 只统计镜像中转目录，无法代表已经归档到其他本地空间/OSS 的资源，因而出现文件很多但 0.00 GiB。保留旧字段的后台容量语义，新增唯一统计 `content_cache={files,bytes}`：合并 `objects.local=1` 与 `object_locations(scope=mirror,state=ready)`，按 SHA-256 聚合、同摘要取一次大小后求和。多个地址、多份副本不重复计数，未完成/失败/房间私有文件不计入公开资源总量。

首页改为“已缓存资源文件 / 资源缓存总量 / 可用来源规则”，从两个公共状态入口透传的新字段读取。全部存储按内容汇总，和当前选择写入的存储无关；兼容旧服务缺字段时显示未知，不能以旧的本地 0 值冒充总量。来源规则数是已启用的 redirect 映射规则，不是资源文件数。

统计使用既有数据库账本，不扫描目录、不访问 OSS 列举所有文件。ready 表示历史上传/落盘核验成功，不代表每次页面访问都远程重验文件；它也不是各云供应商整桶占用或实时账单。本轮未调整现有存储路由、预算、主动缓存数量或删除资源。
