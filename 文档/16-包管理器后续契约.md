# 包管理器后续契约

> 此模块未实现。本轮提供的是输入事实，不是求解器或安装器。

2026-11-12 用户要求的源站缓存自动采集、递归依赖闭包、客户端按内容查询与本地兜底，以 [46-制品依赖约束与客户端兜底方案](46-制品依赖约束与客户端兜底方案.md) 为跨项目实施方案。覆盖普通模组、光影核心、广场/本地/自建整合包和房间；整合包冲突可选择原样继续或自动处理。事实隔离与真实 26.3 光影可行性已验证，源站事实入队/查询基础已实施并本地测试；递归求解、原生通用兜底和决定流程仍未实现，不能以基础接线代替。本文保留求解语义约束，不另存一套采集/查询方案。

## 边界

采集服务回答“这一个具体 JAR 声明了什么”；求解器回答“这个具体实例应选择哪些文件”；安装器执行已批准方案；联机同步分发已确定文件。四者不共享一套混乱的推断状态机。

## 求解输入（后续）

固定 Minecraft 版本、加载器类型/版本、Java、运行侧、已安装制品 SHA-256、用户锁定版本和允许变更范围；候选文件必须有可追溯扫描结果及可下载来源。API 依赖只用于搜索目标项目/候选，最终文件身份和版本约束来自包内证据。Mod ID 与来源项目 ID 是多对多映射，不能只用名字自动绑定。

## 求解语义

Fabric 数组是 OR，字符串组合按 Fabric 规则；Forge/NeoForge 使用自身 Maven 风格区间。required、optional、recommends、suggests、conflicts、breaks、incompatible、discouraged 不能压成一个布尔值；客户端/服务端和加载顺序单独建模。provides 别名、同 JAR 多模组、内嵌库对选择变量的影响也必须处理。

循环依赖不是一律非法，声明关系不保证 DAG。先选满足所有硬约束的文件集合，再单独处理加载器要求的顺序；有合法环时按加载器语义处理，不把拓扑排序失败当作全局无解。拓扑排序不能代替版本约束求解。

## 输出与验收

输出锁文件：每个文件来源 ID/URL策略、SHA-256、扫描版本、被选择原因、增删升级降级清单；无解输出相互冲突的约束及证据路径。例：A 要 B>=1，C 要 B<2，只能在“真实候选文件满足两个约束”时选择 B 1.5，不能 AI 编一个版本。

验收至少覆盖：多父约束交集为空/非空、冲突关系、锁定版本、缺少候选、可选依赖在已安装时版本不兼容、运行侧区别、内嵌提供者和合法循环。求解完成后先预览，再原子安装到暂存/锁文件，失败回滚。前端不执行算法，Python 进程或以后原生服务通过同一契约输出方案。
