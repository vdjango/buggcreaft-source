# Bugg 源站、译文、模组依赖与聚合搜索平台规划总览

> 2026-11-09。独立目录 E:/code/bugg-source。状态以第 11、13 号文档的验收记录为准。

## 产品与本轮边界

一个平台同时提供资源目录、中文译文、真实制品依赖清单与聚合搜索。搜索覆盖名称、简介、正文原文与当前译文，包含全文、名称近似、真实模型语义和相似资源；正文可检索，但不会作为包内依赖事实。资源项目不是模组身份，项目版本不是 JAR 内版本，网页依赖不是包内声明。已交付完整 JAR 落地、受限解压、包内身份和依赖采集、证据保留、持久任务与查询；全文/语义基线及多节点实现见第 32 号，别名库/全站覆盖等仍按后续规划。不建依赖图、不进行自动安装、版本求解或 AI 猜测。

## 已做的架构决定

- 同仓库、模块化后端；API 和采集 worker 分进程。译文/索引 worker 将来独立部署；复用身份、框架和已有库，但不同数据格式/权限的账本与队列分别归属，不能强行共库。
- Python 3.11+ / FastAPI / Pydantic / SQLAlchemy 2 / Alembic；生产 PostgreSQL 18。Vue 3 + Vue Router 4 + Pinia 3 + Axios + TypeScript + Vite 管理前端。C++ 仅在测量证明解析热点需要时替换。
- PostgreSQL 保存关系、任务及解析快照；JAR/证据按 SHA-256 寻址，本地落地后可由独立 boto3 worker 归档雨云/S3。SDK 与持久归档已实现，真实雨云上传尚未联调。事实 SQLite 仅供本地单 worker；迁入原平台的 SQLite/FTS5 是独立过渡例外，见第 04、30 号。初期不要求 Redis、图数据库、Elasticsearch；触发条件见第 04、10 号。
- 用户要求完整迁移后，原平台 42 个 Python 模块、Vue/控制器、协议和测试已迁入，运行不依赖旧目录。保留 AGPL，不迁生产数据。第 30、31 号取代早期“只接外部服务”的决定。
- 搜索作为第四个核心模块：PostgreSQL 原生全文/GIN + jieba + pg_trgm + pgvector；独立索引 worker/FastEmbed CPU 推理服务，词法与语义 RRF。真实 PG/模型已本地验证；API/worker 共用 PG，目录单 hub SQLite，镜像只代理搜索且不缓存。当前实现与限制以第 32 号为准，不宣称生产规模 SLO。
