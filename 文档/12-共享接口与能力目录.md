## 原生版本方言内核（2026-11-12，独立基础已编译，产品尚未接入）

`native/dependency_core` 的 `compare_maven(left,right)` 返回可选 -1/0/+1；`matches_maven(version,expression)` 返回可选布尔，未知/无效返回 nullopt。使用 Maven 嵌套 token/qualifier 语义，不是数字正则或 QVersionNumber。输入有界、纯函数、无线程/网络/存储副作用。C ABI `bugg_dependency_compare_maven` 的 -2、`bugg_dependency_matches` 的 -1 表示未知，不能当作成功；`bugg_dependency_version` 返回固定内核协议。当前只支持已实现的 Maven 区间，Fabric/完整求解未实现；库未接入生产 worker 或启动器安装，不对外声称已有通用兼容校验。保留 Apache 来源/许可及 C++ 修改说明；独立 CTest 和对上游原 Java 24 对比较及逆向一致性通过（Java 仅开发验证）。完整原生签名见内核 include 及 abi.cpp，Python 自动索引不伪造 C++ 条目。

## 缓存制品事实接线（2026-11-12，源码基础已实现，未部署）

`ArtifactStore.receive(chunks,expected_sha256,expected_size)` 是受信内部制品上传的流式落盘/摘要/原子发布所有者，API 不解析归档；取消排空当前磁盘操作再清理，不返回部分成功。`Repository.enqueue_cached/cached_state/public_scans` 负责公开发布标记、原持久队列复用和受限查询；Collector、ArchiveReader、parsers 继续是唯一服务端解析实现。`CacheFacts` 归镜像进程，沿镜像 SQLite 保存上传通知、重放与有界清单对账，沿已有调度生命周期执行；本地/云上传配置不决定是否记录事实。输入、状态、失败与安全边界见第 07、19、46 号，完整实际源码签名由第 18 号索引生成。当前源码提供事实接线，不包含递归闭包、客户端安装或生产规模验证。

## 加载器与核心分发管理（2026-11-12，实施中）

`RuntimeCatalog` 归镜像进程，唯一保存加载器/光影核心目录及停供规则；后台沿用 `/v1/admin/mirror`、原认证、设置和镜像 worker。版本以官方发布身份精确匹配，不解析模组包推断兼容。`runtime_files` 分页读取目录，`runtime_mark` 保存/恢复停供及原因；`runtime_prepare` 只排队，实际目录更新/预缓存复用原 `run_job/ensure` 和容量/存储/摘要规则。页面位于原后台 `/admin/mirror/runtimes`，不创建新外壳。加载器前 N 文件配置从主动缓存页迁到该板块，仍保存同一字段；其他主动缓存规则和任务页不复制。

停供在镜像缓存命中、上游跳转和下载准备之前执行，也过滤加载器版本清单与官方核心版本目录。命中时明确 403 `runtime_blocked`，不能按失败回退回同一个问题上游；上游原目录缓存保存原值，过滤在响应时执行，标记后无需等待目录 TTL。保留实体方便恢复；已有客户端本地 JAR、已发的外部公开/签名链接和已开始的传输不能追溯撤销。完成前用真实 HTTP 的标记/列表/缓存命中/回源和恢复路径验收，具体已实现范围以最终报告为准。

2026-11-11 缓存语义修正以 [第 41 号](41-缓存策略与慢速阈值修复.md) 为准：`cache` 不因快源而跳过副本准备或清理副本；`public_download_response(http,target,headers=None,timeout=1800)` 在异步 worker 内共享有限、安全的 CDN 跳转，失败抛出原 HTTP/网络/地址校验异常，取消沿 await 传播。`resource_demand` 按日聚合近期热度，`prefetch_hot_limit` 控制热门优先数量；`AutomaticSync.batch` 复用原任务、容量、去重及平台策略。128 KiB/s 是判断线，不是限速。

2026-11-11 下载故障修复：`repository_target(source,path)` 在 SourceDiscovery 中唯一归一化 Maven/NeoForge/Fabric/Quilt 坐标；自动发现仍验证同一 SHA-1，不能把不含制品的通用 Maven 仓库假报命中。`Mirror.fallback` 的 NeoForge 国内备用映射覆盖 universal/installer/其他分类及 POM，不再只接受 installer。`Mirror.resource` 在 cache 策略优先使用已有本地/已校验云副本，来源映射不再绕过缓存；redirect/disabled、cloud-only 和容量限制继续生效。下载请求不临时逐源测速。

整合包批量元数据：目录网关仅额外接受官方 POST `/v1/catalog/curseforge/mods`（modIds）及 `/v1/catalog/curseforge/mods/files`（fileIds），每批 1–1000 个正整数、无额外字段或查询参数；复用 Sources 的传输、超时与容量限制，缓存键包含方法和完整规范请求体。密钥仅服务端注入，限流错误保留真实类别；不放开任意 POST 代理。

## 固定缓存选择器

2026-11-11（已部署并针对性回归）：平台密钥复用 Settings 的私有 runtime-config 原子保存、管理员认证与无回显规则。`curseforge_key` 不进入 GET 公共字段，只返回配置布尔值；MirrorControl 复用受保护的内部控制通道同步到下载节点，不下发启动器。热点两平台各取 N 项，按可信 SHA-1/大小对同实体仅下载一次，保留两平台 URL 引用及固定保护；不按名字去重不同版本。

固定缓存选择器：`resourcePins` store 复用单一 `/v1/catalog/{provider}/…` 和 platformFetch 搜索官方资源、读取版本及显示名称。`ResourcePinPicker` 复用 WorkspaceDrawer，用户通过名称选择与版本确认，提交原有 provider/project/version 规格；不要求手填 ID，不引入第二目录服务或修改现有缓存配置格式。旧配置在当前可见分页按需读取名称，查询有界、结果缓存；搜索/版本切换取消旧请求并拒绝晚到响应。请求失败保留选择与原固定列表，添加后仍由既有页级保存提交。

公开下载文案唯一展示数据：`frontend/src/platform/resourceDownloads.ts` 导出 `resourceEndpoints` 与 `resourceDownloadNotice`，镜像页、复用下载区块和文档组合使用；只提供展示信息，不参与后端选源、品牌映射或兼容判断。静态预渲染使用同一 Vue 组件。

## 主动资源缓存（2026-11-11，已部署）

`resource_prefetch` 是镜像 settings 的配置域：enabled、limit（每平台每类 0–10000 个热门项目）、types、providers、refresh_hours、pins（平台/项目/可选版本）。热门每项目选择官方返回的最新主文件，手动项目可固定具体版本；不把远程目录写成包内依赖事实，不执行下载的 JAR。`ResourcePrefetch` 仅负责官方目录发现、持久候选和固定引用，HTTP 复用 Sources.get，实体下载/校验/续传/配额/云端去向仍唯一归 Mirror.ensure/MirrorCloud。

管理员沿用 POST `/v1/admin/mirror`：action=resource_prefetch 只启动既有镜像作业；action=resource_files 返回分页明细。自动作业沿用 refresh_loop，同一时刻只运行一个镜像作业，取消沿用 cancel；状态返回 discovery/download、发现数、已缓存/复用/失败/容量不足与预计字节。数据/配置均归镜像节点，hub 只认证并转发，不在 API 内下载。固定引用保护所有内容哈希别名的最后副本，仍受磁盘与空间预算限制；删除固定规则只解除保护，不删除文件。默认关闭；开启自动更新后按保存的范围调度，保存 HTTP 请求本身不执行下载。首轮线上小批量与配置边界见第 37 号验收记录。

源质量快慢阈值允许相同边界（优秀/良好仍按原成功率区分），慢速值高于快速值才拒绝；保留线上已有 512/512 设置，不能因保存无关缓存设置阻止操作。

## 光影核心候选清单（2026-11-11）

`CatalogGateway.shader_runtimes`：公开只读 GET `/v1/catalog/shader-runtimes`，返回版本化候选项目标识、名称、候选加载器与包内识别标记；清单不承诺每个游戏版本均支持。具体版本、依赖和下载地址仍从现有官方目录网关获取，沿用同一源地址、限流和 HTTP 客户端，不另存下载链接或实现另一版本求解器。初始候选为 Modrinth 官方项目 Iris YL57xq9U、Oculus GchcoXML；个人核对各自平台/作者说明与实际文件后登记，不把项目 tags 直接当作单文件兼容性。

## 成都镜像与本地挂载目录（2026-11-11）

镜像进程继续唯一持有 settings、缓存账本、NodeAccess 和存储证书；管理站通过现有 `/_internal/control` 协议读取、保存配置及执行节点/证书操作，不读取另一台服务器的本地目录或 SQLite。可选 `TRANSLATION_MIRROR_CONTROL_PORT` 指向本机加密 SSH 转发端口；为 0 时仍连接本机 mirror_port 并启动镜像子进程。远程模式下不再启动第二个镜像写入者，失联返回 503，不在管理站保存伪成功副本。控制端口与令牌不公开；CDN 的 `/_internal/` 始终拒绝。

`settings` 操作沿用原校验、原子 JSON 写入和缩容保护，绑定文件的空间不可变更根目录或目标身份；目录必须真实存在且服务用户可写，不自动创建挂载点。`room_nodes` / `cloud_certificate` 转发原实现，保留现有鉴权。MirrorControl 仍是管理 HTTP 桥，Mirror/MirrorCloud 是实际配置和存储唯一所有者。

成都公开域名沿用 `mirror.bugg.icu`；TLS 由既有 Certbot 与 `certbot-dns-tencentcloud` 2.1.1 插件完成 DNS-01，不新增腾讯签名、DNS 客户端或另一套证书引擎。凭据只存服务器 root 可读的独立配置，定时器复用 Certbot renew，部署钩子检查 Nginx 后重载。该运维插件属于可选 `acme-tencent`，不进入浏览器或一般服务运行依赖。

## 本地分发与完整房间缓存（2026-11-11）

`mirror_storage.LocalStorage` 实现既有存储适配契约，输入已挂载的绝对目录、容量/保留空间与摘要对象标识；复用 MirrorCloud 的持久队列、空间预留、逐文件进度、去重、到期清理和失败状态。不创建缺失的挂载目录；文件在线程中按 1 MiB 流式复制并验证 SHA-256，原子发布，错误不发布半文件。没有新增业务数据库、客户端测速器或存储任务队列。

`Mirror.local_storage_file` 负责 `GET/HEAD /_storage/{profile}/{key}`：域隔离 HMAC、有效期、目录边界校验后，复用 Egress 准入、正在服务计数和 PinnedFileResponse；支持 Range/416/HEAD 与断点续传，禁止匿名列目录，HEAD 不扣传输字节。签名密钥复用仅服务端可读的 control-token，签名 URL 不进入访问日志/CDN公共缓存。

`room_cache_policy=adaptive|full` 归 RoomCache.decision 所有；默认 adaptive 保持原来源质量判定，full 优先使用已验证缓存，否则请求房主上传缺少的摘要。名称不作为缓存身份，默认保留 8 小时，可配置；容量不足仍返回既有逐文件容量原因，不假装全部完成。客户端继续使用现有“加速缓存”开关、房间清单与上传明细，无需新增协议或依赖启动器运行。源站自动质量检测复用已有观测和探测预算，不在每次下载前测速。

成都 edge 独立 mc-mirror 进程绑定回环；目录/翻译事实仍由上海单 hub 写入。共享 200 Mbit/s 出口用 Linux HTB/fq_codel 做 IPv4/IPv6 聚合调度：总上限 190，HTTP 上限 170，控制/中继优先；Egress 只做准入，不冒充包速率控制。正式入口为 mirror.bugg.icu HTTPS，裸 HTTP 重定向；私有文件不进入公共缓存。服务使用 ProtectSystem=full，/etc、/usr 等系统目录保持只读；/mnt、/srv 等挂载路径按 bugg-source 用户的 Unix 权限访问，不再要求每添一个目录都修改 systemd 单元。ProtectHome、非 root 和 NoNewPrivileges 保留；页面不会替管理员修改磁盘权限。

## 启动器目录筛选网关（2026-11-10）

`mc_translate.catalog_gateway.CatalogGateway` 是官方目录查询的唯一适配者，复用 Sources.get、Sources.semaphore、API.rate 和应用 http 会话。公开 GET `/v1/catalog/curseforge/{route}`、`/v1/catalog/modrinth/{route}`，保留官方参数及 JSON 响应；具体路径、数组上限、迁移反代见第 33 号。不得抓多页后在本地过滤，不重算 total，不将上游分类写入包内事实。输入只允许所登记的元数据路径，不接受外部 URL、浏览器 Key 或写入方法。

CF Key 只来自 Config.curseforge_key；缺失返回 503。非法参数 400、未开放路径 404、平台限流 429、上游异常 503；取消透传 aiohttp/Sources，退出由原应用关闭会话。短期缓存最多 32 份，每份受 Sources.read_json 的 1 MiB 限制，键包含平台、路径、全部筛选和分页；复用源并发上限，不新增线程、数据库或文件下载服务。当前只在 hub 服务，镜像保持既有 hub_required 行为。

## 2026-11-11 分类主动准备与冷缓存合并

read_settings/validate_settings 的 prefetch_category_limits 是六类资源唯一数量配置，各值 0–10000，0 暂停该类自动准备，不删除已有文件。AutomaticSync.batch 先按近七天请求热度、其后清单版本优先级排序，在扣除已缓存文件之前截取各类前 N 项，避免每轮扩大工作集。无玩家请求也会准备；遵守缓存/备份策略、客户端平台、容量及原并发限制。非模组资源没有官方热门榜时只用本站请求量和版本优先级，不虚构热度。

Mirror.serve 对已判慢速或不可用的冷资源复用 backup/ensure 的原下载任务，最多 64 个请求等待、最多六秒，shield 不因单个玩家离开取消共享准备；超时/失败仍沿原候选来源回退，不返回空结果。后台冷补齐仍限制两条不同资源下载，同一 URL 合并；云端模式只有 ready 副本才可提供下载。自动同步的有界批次先于大型模组榜单扫描，业务策略只有上述所有者一处。MirrorSettings 及 mirrorWorkspace 只编辑/提交同一配置，网页离开沿原 store 取消和停止轮询。

目录版本列表可超过原翻译元数据的 1 MiB 限制。`Sources.get(url,headers=None,limit=1048576)` 复用 read_json 的既有有界流读；默认调用不变，CatalogGateway 显式传 8 MiB，与原生客户端一致。缓存同时限制 32 项及 32 MiB 序列化大小，过期/替换/淘汰均维护字节账本；不增加网络客户端或无界缓存。首次回源仍最多 35 秒，客户端目录无进展时限 40 秒、总时限 45 秒，用户取消仍立即生效。

CatalogGateway.arguments/read 的现有 MR 白名单增加 `GET /version_file/{sha1}`：只接受 40 位小写 SHA-1，无查询参数。输入输出为官方元数据原文，失败复用原有 404/503；Sources 的连接池、容量及应用生命周期拥有请求，缓存仍最多 32 项。用于启动器整合包导出的文件身份查找，避免绕过所选 Bugg 基址；不承担文件下载、指纹批处理或依赖求解。

# 多存储自动放置契约（2026-11-11）

`MirrorCloud` 继续唯一拥有位置账本、空间预算、预留与传输。新增路由 `mode=auto, profile=''`：按存储列表顺序选择已配置且可用的空间，自动写入使用 95% 容量水位，保留磁盘安全余量并扣除在途预留；不足则选择下一个。房间只选私有空间。读取始终按已核验摘要查询所有位置，不用当前写入路由限定已有副本，也不为切换存储重新上传。全部空间不足进入 waiting_capacity，恢复容量后自动重试；不删除旧文件。默认缓存仍为有界中转，目标核验后才能释放。

`profile_capacity` 返回已用、预留、可写容量及预警；本地磁盘查询在 worker，云空间按本服务账本计量，不谎称云提供商全桶占用。状态 API 汇总存储池与明确告警。主动准备设置只保留规则；运行、暂停/继续、手动重试、进度和缓存清单归作业页，切页不取消后台作业。

配置页“主动缓存”是资源准备规则的唯一编辑入口：游戏文件分类上限、平台、排行数、更新周期、类别、目录平台和固定项目均经 `mirrorWorkspace.save('downloads')` 提交；任务页只调用 `resource_prefetch_start`、`resource_prefetch_pause` 与 `resource_files`，显示运行/排队/暂停状态。手动请求持久化为 `ResourcePrefetch.requested`，当前任务结束后排队启动，重复请求幂等；暂停只取消同类作业并跨重启保留，不影响其他作业。所有来源共用 `MirrorCloud` 摘要索引，不另建预缓存副本。

`MirrorCloud.egress(profile)` 是空间月流量的唯一判断所有者，状态增加 `remaining_bytes`（未设限为 null）与 `warning=near/blocked/null`。`download_url` 在原 `egress_lock` 内检查完整对象的预留后用量，超出停供线跳过此位置；所有位置不可供流则返回 None，由原上游回退返回重定向。前端只呈现状态，不再重复推导预算状态。已下发的云签名链接不能撤销，公开桶也不能用本站账本限制直接访问。

## 2026-11-12 兼容配额与停供

`resource_prefetch.compatibility` 是热门资源、加载器和核心的唯一游戏范围/配额规则：全部、最近 N 个正式版本或指定版本，每游戏每项目最新 N 个兼容发布，允许逐游戏覆盖数量。`ResourcePrefetch.compatible_releases` 先排除停供再计数，将跨游戏共用文件合并；只接受明确支持列表，不补全最小/最大版本之间的空洞。

`RuntimeCatalog` 归 Mirror 持有。files 最多 50 条/页；mark 持久化类型/版本/原因、立即更新策略；request/discover 复用原准备任务、下载及存储。目录网关每次响应叠加当前策略，旧 JSON 缓存不能绕过停供。下载、摘要地址、回源和重定向前统一检查，已观测官方身份/SHA-1 别名共用规则；未知别名不声称已识别。

cleanup/purge 每轮最多处理 5 个问题对象，复用位置账本和传输锁，删除已登记本地/云端副本，保留发布身份和摘要停供记录。活跃对象延后，失败重试；停供不占配额，下一兼容版本补位。恢复后若文件已删则重新准备。

`LocalStorage.put_verified` 校验 SHA-256、写临时文件再发布。普通磁盘保留硬链接提交；COS/FUSE 不支持硬链接时在写锁内改用重命名，再核验最终内容。已有同键不同内容拒绝覆盖，临时文件 finally 清理。写入/删除错误转为 StorageError，管理桥显示真实服务端失败，不一律伪报 mirror_offline。实测及恢复见第 45 号。
