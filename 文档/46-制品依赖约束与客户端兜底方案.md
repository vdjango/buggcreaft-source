# 制品依赖约束与客户端兜底

## 光影核心受控清单与按游戏版本验收规划（2026-11-12，待实现）

### 版本目录、持久事实与客户端规划补充（2026-11-12）

- 源站负责持久收集并发布各平台项目、发布、文件、游戏版本和加载器声明，以及与具体文件摘要绑定的包内依赖约束；启动器优先批量读取源站，按目标游戏版本和完整加载器构建遍历候选、核对依赖并生成安装计划。平台固定依赖和包内实际声明分别保留，不得把某个成功组合写死成通用规则。
- 源站查询不到是正常状态：客户端继续使用上游目录或本地文件解析，并明确保留未知状态。源站不可用、部分结果、超时和解析未完成均不能伪装成零依赖或确定不支持。已成功采集并发布的记录必须落入持久目录，按来源、项目、发布、文件及已核验摘要查询；缓存过期、上游失败或重启不能使其变成无记录。旧快照可标记过期并后台刷新，但要返回采集时间、修订、状态及证据；上游删除、文件重传或人工撤回作为可追溯的新状态，不能静默抹掉历史或继续声称可下载。公共目录与私有文件事实隔离，禁止用摘要查询探测私有文件。
- 安装光影包时列出全部已发现的核心候选及其具体版本，分别展示平台声明、依赖可解析情况和人工/实测状态；多平台项目与文件只有摘要核验一致时才关联。默认自动选取依赖可解析的候选并补装必要依赖，用户可以选择其他候选；选中后按该精确发布重新规划和校验，失败时给出原因，不悄悄改选其他版本。已安装核心须核实文件身份与约束，避免重复安装。版本列表分页或预算未遍历完成时显示部分结果，不声称已覆盖全部版本。
- 增量交付顺序：先固定源站发布记录及 SHA-1/SHA-512 到已核验 SHA-256 的公开绑定和批量查询契约，测试重复查询、重启、上游失效、重传、撤回和私有隔离；再让客户端优先按发布身份批量读取持久事实，缺失时回退目录与本地解析；随后接入按文件声明求解、候选列表和选择界面，并对全部加载器与切换目标/版本、过期响应、取消和回滚做端到端测试。最后完成数据采集回填、实际安装及世界内效果验证，再部署和交付。现有按 SHA-256 的事实接口仅在文件已下载后可用，尚不能独自满足安装前按发布查询的要求。

本节为新增规划，覆盖启动器支持的全部加载器及游戏版本；不把 NeoForge 局部结果当成其他加载器已支持。先复现 26.1.1 + NeoForge 和切换内容版本丢依赖，再扩展全量。本节不代表功能或验证已经完成。

### 现状与数据来源

当前启动器的光影核心候选清单请求 Bugg 的 `/v1/catalog/shader-runtimes`，失败或格式不匹配时回退程序内清单；游戏版本和发布文件等目录数据按来源顺序经 Bugg 目录网关或其他可用来源获取。Bugg 目录网关转发上游结构化数据，不等于数据均经过 Bugg 人工核验。2026-11-12 实际查询 mirror.bugg.icu 返回 Iris/Oculus 候选和两条 26.3 精确例外；本地资源文件的例外为空，线上与本地不能混为一谈。现有清单不是按游戏版本的完整实测兼容表。

按 SHA-256 查询文件依赖事实和客户端本地 JAR 兜底已有未完成源码；基础接口未部署，不能声称当前用户安装流程已完整使用。现有候选和规则不证明 Forge、Fabric、Quilt 或其他加载器端到端支持，必须逐个复现并记录。来源切换或源站不可用时仍需正确处理，不能把来源 API 的空依赖当作包内无依赖。

### 按游戏版本组织清单

以**具体游戏版本**为第一层；其下按加载器家族、完整加载器构建、核心具体发布及文件 SHA-256 记录。覆盖启动器实际提供的所有加载器，包括 Forge、NeoForge、Fabric、Quilt，以及实际提供的其他加载器和原版路径；分别说明可用核心及安装方式、无候选、待验证或不适用的依据。核心与光影包分别记录；光影包不混用核心 JAR 的模组依赖语义。

每条记录保留来源及项目/发布/文件 ID、摘要、原始平台标签、包内按目标加载器的声明及解析器版本、核心与依赖各自具体版本和摘要、依赖范围及来源、必要/可选/冲突、运行侧、预发布策略、游戏和加载器完整版本、已知问题及规则版本。包含来源证据、审核人和时间、验证环境、测试方法、日志/截图以及复核条件。跨平台文件仅在摘要核验一致后关联；重传、换文件、换加载器构建或依赖变化形成独立记录。明确区分上游声明、文件事实、人工审核、实际安装、启动和世界内光影生效，不能互相冒充。

优先选择已审核且适用于完整目标的组合，按精确核心与依赖文件锁定，交由统一求解和安装流程检查活动文件、完整约束及冲突，自动补装必要依赖；不覆盖作者原声明，不静默替换用户已有活动模组或绕过整合包锁定。核验下载摘要；版本切换重新生成完整计划和依赖，丢弃过时响应。已有文件满足时复用。没有已验证组合时展示真实状态与原因，仍按统一事实和求解流程判断可否安装；不能因为没登记就宣称不支持，也不能把未测显示为已验证。

### 异常发现与人工介入
按用户补充要求，安装光影包时默认根据具体游戏版本和加载器自动查找、添加适用的光影核心及其必要依赖。人工维护用于标记具体环境与文件组合的可用、不可用或待验证状态及证据，不要求用户手动选择核心；没有人工结论的候选保留待验证状态，不能直接称为不可用或已通过运行验证。

对登记为应检查依赖的核心，新发布的上游必需依赖突然为空、与同一发布的 JAR 声明不一致，或较相邻已审核发布发生意外变化时，建立持久待审核事项，保存两边原始证据、发布和摘要；不把空列表自动解释为零依赖，也不复制上一版本依赖。新加载器、元数据缺失或解析失败、内容重传、上游撤回、验证组合冲突或运行失败同样触发复核。空依赖是异常线索，不必然是错误：作者可能确实移除、内嵌或由加载器提供依赖；取得具体文件与证据后人工判定，可登记经核验的真正零外部依赖。

待审核项不得自动发布为已验证组合，也不得默默沿用旧版本锁定；客户端可基于可信文件事实和统一规则求解，缺少可信映射或无法确认必要依赖时说明原因并阻止不可靠的自动补装。不能把缺数据直接归因为游戏不支持。管理端复用现有依赖采集、作业和权限体系，提供差异、证据、审核结论、发布/撤回、责任人及审计记录；未经授权的上报只能是线索。已发布记录支持版本化、撤回、回滚与失效，客户端校验 schema、摘要和目标环境，保留有界可信快照并遵守撤回策略。服务不可用时区分离线快照与最新状态，继续本地事实检查，不将过期结果称作当前验证。

首批持久审核入口复用受信发布观察：已登记光影核心的发布元数据必需依赖为空时，以平台、项目、发布和上游文件摘要组成身份，记录原始观察及对应采集任务，初始状态为待审核。`GET /api/v1/shader-reviews` 需要现有管理鉴权，按游戏版本筛选；`POST /api/v1/shader-reviews/{id}/decisions` 需要管理鉴权，保存非空审核人、结论及说明并追加审计历史。此入口只登记异常线索及人工结论，不发布安装组合、不意味着该发布确实错误或已通过运行验证；后续文件解析差异及组合发布仍须接线。

### 实施顺序与验收

1. 固定调查基线：枚举具体游戏版本、启动器支持的加载器与构建、可识别核心全部发布，记录数据来源和枚举时间；新增发布可增量复查。先复现 26.1.1/NeoForge、版本切换和各加载器问题，保留失败原因。范围内每项区分无候选、未尝试、安装失败、运行失败和已生效，不能把筛选当作实测。
2. 扩展现有源站事实、候选清单与任务所有者，建立按游戏版本查询的版本化受控记录、异常队列和审核发布流程；保留原始数据，不能引入第二套冲突的依赖事实。接口按具体目标返回记录、证据状态和未解决原因，下载地址沿现有权限与有效性规则取得。
3. 启动器所有加载器接入同一目标匹配、依赖求解、文件暂存和原子提交路径，切换版本重新解析；源站缺失、无网络或切换其他来源时使用本地受限读取。按各加载器方言处理，不能仅支持 NeoForge；保留用户选择和整合包约束。
4. 回归 API 空但 JAR 有依赖、真正零依赖、依赖新增/删除、固定版本与多父约束、冲突、不同加载器同文件、旧响应迟到、源站不可用、人工撤回、重传、取消和回滚。逐游戏版本、加载器及构建、核心发布保存安装结果；实际启动并进入世界、选择光影包、核对日志与效果后才能标为光影生效。无法执行或不可下载的条目保留未验证及原因，不用抽样冒充全量。
5. 输出可查询的完整矩阵和易读报告：每项列出游戏版本、加载器完整构建、核心及依赖版本和摘要、光影包、来源、结果、失败原因与证据。固定快照时间及枚举范围，持续增量更新；运行未测项明确列出。产品实现、部署及用户实际入口验收完成前均标记未完成。

状态：2026-11-12 方案与可行性验证已完成；源站事实入队/查询接线已开始实施并进行本地测试，尚未部署。递归闭包、客户端通用兜底/决定/求解及最终自动安装验收仍未完成，不能据本文声称整套功能已交付。

## 目标与唯一所有者

每个缓存文件都产生一个可追踪的元数据处理状态。JAR 收集声明事实；图片、普通资源等明确标记不适用，光影 ZIP 的加载方式/包格式与核心 JAR 的模组依赖分开。不把没有元数据、解析失败、尚未处理表示成零依赖。

服务端继续复用现有 Collector / ArchiveReader / parsers / Repository；不另写镜像专用 TOML 解析器。客户端补充原生包内读取与约束检查，通过同一版本化事实契约与一致性样例对齐，运行不依赖 Python 或 Bugg 源在线。源站可以生成指定目标环境的递归闭包与候选锁定方案；客户端仍是当前实例的检查、用户决定、安装与回滚唯一所有者，不能无条件执行与本地活动文件不一致的远端方案。

## 统一覆盖的安装入口

普通模组首次安装、补装/更新、光影核心及其依赖、广场整合包下载、本地 ZIP/mrpack/buggpack 导入（含我们自行整合/从启动器导出的包）、房间内容同步，均消费同一份文件事实和同一个约束检查结果。不同入口只决定安装意图和是否允许提出替换方案，不各自解析 TOML、判断版本或另设某个模组专用补丁。已安装活动模组也参加检查，禁用模组不作为依赖提供者。光影 ZIP、资源包的包格式/加载方式单独表达，不能套用核心 JAR 的模组依赖。

平台 API 的游戏版本、加载器和发布文件标识保留为结构化筛选条件，包内约束保留原语义；不从文件名、展示文本或正则提取的数字猜兼容性。未识别的格式/表达式明确给出未能核验，不能等同于兼容或零依赖。

## 整合包原样安装与显式例外

整合包作者锁定的文件集合是原始输入。声明上存在冲突并不等同于实际一定不能运行；作者可能有已验证的组合或绕过机制。安装前分别展示缺失依赖、版本不满足、声明冲突、未知元数据和有实际失败证据的运行问题，列明具体文件、声明者及要求。不得因检查器发现冲突就自动升级、降级、删模组或换加载器。

对依赖/兼容性检查结果统一提供“保留原版本继续”“自动处理依赖”“取消”，详情展示具体冲突。“自动处理依赖”对外部作者包、我们自行整合的包和本地导入包同样适用；点击后授权在本次目标实例的暂存区计算并验证调整方案，不改动输入归档。没有可靠候选、无法建立 mod_id 与项目的可信映射或超出预算时，明确说明无法自动处理，并保留原版本继续/取消的选择，不按相似名称下载。

自动处理优先最小变更：保留符合约束的既有文件，仅为必要依赖补装或调整具体发布，并重新检查整组交集及已知运行问题。锁定文件的偏离记录原 SHA-256、选中 SHA-256、理由和所解决的约束；不冒充作者原锁定内容。不能静默切换游戏版本/加载器家族、启用禁用模组或删除用户内容；若仅有 beta 候选，明确标出候选性质并遵从当前接受预发布的选择。取消/下载失败/最终仍有冲突时不发布调整后的半成品，保存可重试的已校验暂存和原因。

保留原版本继续不会改写原包和源站事实，不将冲突标成已解决或已经运行成功。首次未经选择不悄悄放行，也不悄悄替换。下载失败、摘要不符、危险归档路径和损坏文件仍按原完整性规则失败，不能用兼容性例外跳过它们。

安装意图统一表达为 requested_content（用户主动选定的新内容）、authored_pack（作者锁定集合，包括自建包）和 room_manifest（房主锁定集合）。后两类未经选择不能改变文件锁定；自建/作者包的自动处理必须由上述显式选择触发。房间是否接纳调整后的组合仍由房间原协议决定，客户端例外不伪造同步一致。普通模组的自动补依赖也不能擅自替换用户已有活动模组；需要调整时回传同一个检查结果及方案，由原安装确认流程承接。

检查分两段：安装 API 元信息用于预览；所有实际文件暂存后以包内事实做最终检查。首次最终检查需要决定时，保存可恢复的暂存状态并返回 needs_dependency_decision，避免用户确认后重新下载。GUI 只展示由工作线程生成的结果、发送选择，不解析包、不自己判断冲突。取消保留可复用的校验暂存，不提交半个实例。

继续决定保存到当前实例的安装收据：包含决策 schema、安装意图、完整活动文件集合的 SHA-256、游戏完整版本、加载器类型及完整构建、检查器/规则版本、每个冲突的稳定标识及用户选择。只有完全相同的组合允许复用决定；更新一个文件、新增依赖、切换游戏/加载器后必须重新检查，新增冲突重新确认，不保存“此模组永远忽略”或全局关闭检查。事实快照、求解建议与用户决定各有独立字段，不互相覆盖。

## 文件与版本身份

权威键为 `artifact_sha256 + parser_version`。每条包内模组进一步带容器路径、元数据路径、序号、mod_id 和加载器；同 JAR 多模组、不同加载器和内嵌包分别保留。来源 `provider/project_id/release_id/file_id` 只是到该内容的观察映射，不能以项目名、文件名或“最新版”覆盖事实。

例如 B 的 v1 JAR 声明 A `[1,2)`；B 的 v2 声明 A `[2,3)` 并新增 C。两份 JAR 各有独立不可变快照，查询/安装 v1 不能读到 v2 的依赖。相同版本标签但不同加载器或重新上传、摘要不同，也必须分别采集。URL 相同换内容重新建映射，旧快照保留；多个存储空间放同一内容只复用一份事实。

依赖保留原始关系、原始版本表达式、运行侧、排序和证据位置。Forge/NeoForge 使用 Maven 语义，Fabric 使用其版本谓词；可选依赖是“未安装不要求，已安装必须符合”，不是忽略版本。冲突、建议、必需、内嵌提供者和别名不得压成一个布尔值。

## 源站缓存接线

### 统一入口与运维控制（2026-11-12 补充）

采集范围同时覆盖已缓存文件、客户端实际请求的发布文件和热点准备选中的发布文件。目录列表只登记结构化发布观察；文件采集仍由有预算的独立 worker 执行，不能在目录/下载响应里解析 JAR。三个入口共享摘要去重、采集队列、解析器版本和递归发现记录。实时请求未采用缓存策略时也不能漏掉；发现尚无文件摘要/可信 URL 时记录待发现，不把它算成采集成功。

后台复用原“采集任务”页面作为独立“依赖采集”入口，不再增加第二套作业后台。持久开关暂停 worker 取任务，并在工作检查点安全释放正在处理的租约；队列和观察保留，继续后沿原任务恢复。单项取消、失败重试继续使用原接口。页面展示入口来源、摘要、采集/递归状态与失败原因，区分“声明已解析”和“依赖闭包已满足”；不能把运行中的进程或一次人工触发当成完整闭包。

完整文件下载并核对摘要、提交缓存对象时，在镜像现有持久账本登记待采集事件，先落盘再通知独立采集服务；不在下载请求中执行解压。通知失败或重启仍可重放，不使用容易丢失的纯内存回调。入队沿用 Repository 的去重、租约、取消、优先级和预算，采集沿用 Collector。

事件以摘要/解析器版本去重；缓存对象成功、通知尚未持久化时崩溃的间隙，由有界清单对账补齐。镜像与房间各自账本不假装处于同一个跨库事务。普通下载、本地空间、云空间和房间缓存都进入同一通知入口，不把本地模式下会提前返回的云上传队列当成唯一触发点。

文件已在可信缓存中时使用其摘要绑定的本地/存储读取接口，不重复回公网下载。只接受配置的内部鉴权与内容摘要，禁止公开任意本地路径和任意 URL 抓取。云副本与本地副本沿用现有位置账本；解析器不成为第二个存储调度器。文件转移或本地缓存释放不会删除已经保存的依赖事实及证据。

持久状态至少区分 pending/running/complete_declared/partial/unsupported/not_applicable/failed，并记录解析器版本、失败原因、尝试时间；解析失败不阻断普通文件分发，但不得声称已确认兼容。既有缓存按摘要分页回填，有界批次、按需优先；解析器升级只生成新快照，不改写历史。不能在每个请求扫描整个缓存或重新解压同一文件。

跨节点提供缓存节点到受信采集服务的内部制品上传：发送完整缓存字节及预期 SHA-256，接收方流式暂存、重验摘要，入原持久队列；解析只由原 worker 执行。它是无就近采集能力时的受限回退，不应成为所有大文件绕上海再传一遍的默认部署方式；就近采集和统一汇聚见下节。避免让服务端按客户端提交的任意 URL 抓取，也不假定成都/上海共享本地路径。内部上传使用单独服务凭证、HTTPS（回环可 HTTP）、有限大小和超时，沿原 HTTP 连接池；公开来源与房间私有来源分开登记，私有上传不因知道公共查询接口而暴露。公开查询只返回已显式发布的事实。

### 就近采集、汇聚与暂存回收

优先在缓存文件所在的受信源站运行同一 Collector worker，约束事实和小型原文证据汇聚到统一查询服务，避免 200 GiB 资源经低带宽控制服务器再复制一遍。公开客户端永远不提交本地路径；内部任务只带受控 scope/摘要，由对应采集节点根据部署允许的根目录和位置账本定位。任务带采集节点归属/能力，跨机器的 worker 不能误领一个只在另一台机器有本地字节的任务；重试和迁移重新选择可读的实体位置。

就近 worker 的发布需要独立节点身份、权限和解析器版本白名单，证据内容重验摘要，公开/私有范围单独授权。仅运维明确受信的采集节点可提交已验证事实；普通客户端及未受信贡献节点不能通过上报 JSON 变成权威事实，仍须把完整文件交给受信 Collector 重验。统一服务与源站数据库/密钥不暴露给这些节点，不让采集器越权读取镜像私有 SQLite。

采集暂存 CAS 是受限中转空间，不能成为第二套永久保存全部 JAR 的资源库。每次入队须有空间与在途字节预算；文件固定/复制/硬链接只在受控根及不可变摘要下进行。完成快照后，保留必要元数据原文与摘要，完整根 JAR 的暂存按租约和保留期回收；若原有归档任务仍需要它，先等归档交接完成。Windows 打开文件、并发不同解析器版本、取消及崩溃都不能留下读到半文件或清掉其他任务输入的情况。空间不足应停止新的采集接收并预警，普通资源分发继续沿原位置/上游策略，不用耗尽磁盘换取无限待解析队列。

解析器升级按优先级重新取原缓存/多存储实体，或按已知来源重新准备；不会因为保留了旧事实就假称还保留完整 JAR。证据原文若迁到云存储，必须沿原位置和预算机制可读取，不留下指向已删文件的 object_key。此部署与回收部分尚待实施和验收，现有入队/上传接线仅是基础，不代表大规模跨节点链路已完成。

## 源站递归采集与依赖闭包

### 三类结果不能混为一谈

declared_facts 表示从这个具体文件中读到的真实声明；resolved_closure 表示给定游戏/加载器/运行侧/策略下，找到一组满足声明及已知问题规则的具体文件；runtime_verified 表示该组摘要在记录的环境完成了实际启动或光影生效验证。前两者不能自动升级成第三者，也不能承诺以后绝不崩溃。作者漏写或写宽约束、配置冲突、Mixin/API 变化、驱动问题等可能超出声明范围；本次 Iris/Sodium 已有实际例证。

### 文件事实图与环境锁定图分开

事实边的起点为 artifact_sha256 + parser_version + container_path + mod_id，终点是带命名空间的目标模组 ID/项目及原始版本谓词，并保留关系、运行侧、可选条件和证据位置。只有作者或可信平台确实固定具体文件时，事实边才含固定发布身份。范围依赖不能在事实表中永久改写成“当前最新版文件”。

给定环境生成单独的锁定快照：根文件摘要集合、完整游戏版本、加载器类型及完整构建、client/server 运行侧、已有活动文件/禁用文件、预发布策略、允许的修复例外、规则及求解器版本共同形成指纹。每个选中节点固定发布身份、SHA-256/大小及来源；每条锁定边指向该具体节点，同时保留原事实边。B v1 与 B v2、同名重传、不同加载器必须走不同节点；同一个 A 文件被十个父节点引用只采集一次。

多个父节点对 A 的要求必须求交集，不能各自选好再覆盖。已由游戏、Java、加载器、内嵌 JAR 或 provides 提供的能力参加约束检查，不按普通模组再下载。必需循环 A→B→A 使用去重和连通分量处理：循环本身不等于无解，选定节点全部满足约束才能闭合。已安装的可选依赖照常检查；未安装的可选/推荐依赖默认不扩散，只有用户/缓存策略显式要求才加入，避免扩成全站采集。

加载顺序与版本可满足性分别检查：BEFORE/AFTER 等顺序要求可能使版本都符合的环仍无法加载，不能仅靠去重放行。Fabric 的建议/弱冲突、NeoForge 的 discouraged 与真正的必需/不兼容关系按原方言确定严重度，不把所有关系当强制依赖。Fabric 表达式数组的 OR、同一谓词中的 AND、Maven 区间的并集、预发布/构建标记及非标准版本都保留原义；未知表达式明确未能核验。

同一摘要被安装为两个不同活动 JAR、两个不同文件声明同一个 mod_id，与服务端按摘要复用事实是两件事：前者可能导致重复加载，必须在实例检查中指出；不能因为事实去重就忽略实际重复文件。同一多加载器 JAR 中的不同元数据则按目标加载器选择，不能误报两份模组。

### 顺藤摸瓜的执行流程

1. 缓存根文件完整落盘并校验后，原采集 worker 解析、入不可变快照，再持久化待展开的边。单个文件事实可立即供查询；闭包未完成必须明确 pending/partial，不能返回假的完整清单。
2. 先复用本地/多存储已知内容和已采集事实，再通过平台结构化依赖项目/发布 ID 和已验证的 mod_id↔项目↔文件摘要映射寻找候选。不根据相似名字、slug 或文件名猜项目；没有可信映射时保留 unresolved_target，客户端同样不能胡乱下载。
3. 使用明确的目标游戏和加载器筛选候选，按版本策略及实际谓词裁剪；下载候选的真实完整文件、核对摘要、复用 Collector 入库，然后展开它的必要依赖。接口缺版本范围时，以实际包内声明补全；接口固定发布与包内声明冲突时保留两份出处并报冲突，不默默丢掉其中一份。
4. 候选失败可以在预算内回退并重新计算交集；不能通过换源绕过同一文件的约束。每次只扩展当前求解需要的候选，不下载范围内每个历史发布。根有多个游戏支持范围时，仅为配置的热门/指定目标环境做闭包，其他范围保留事实、按需补齐，不枚举全部游戏×加载器构建的笛卡尔积。
5. 选定组合闭合后保存锁定快照及全部约束链。新增上游发布只产生新候选和新快照，旧闭包及正在执行的安装不被“最新版”覆盖；同 URL 内容变化按新摘要处理。旧快照仍可审计，是否仍可下载另行判断。

### 预算、恢复和存储边界

配置分为“采集事实”“展开闭包”“保留实体”，不再混成一个重复的主动缓存开关。每个完整制品登记处理状态；只有受支持的归档才进入受限元数据读取。模组 JAR、含明确文件清单的整合包、光影 ZIP/资源包采用各自声明格式，普通图片/音频等明确不适用。未知 ZIP/新格式先记录 unsupported，不能仅凭后缀把整合包当无依赖；整合包清单中的精确文件集合成为根节点集合，所有入口复用它，覆盖我们自行导出的包。

扩展任务沿原 Repository 的租约、取消、队列优先级、重试、每日流量和空间预算；持久化根、目标环境、待处理边、选中候选、尝试记录和预算消耗。实例按需任务优先于后台热门准备，根之间公平轮转，不能一个根占满全部 worker。显式限制每根节点数、每目标候选数、扩展深度、总字节、耗时及全局并发；到限返回 partial/budget_exhausted 和可续跑位置，重启不重复下载已完成节点。失败依赖不得被标成零依赖或将整棵树当已完成。

依赖实体沿现有公共资源缓存及存储位置账本保存；同摘要跨本地/OSS 空间复用，不因位置不同重新采集。递归采集不能绕过 OSS 流量预算、停供标记、版权/分发限制或磁盘预警；预算耗尽可明确保留外部上游入口或不可用状态，但不能声称本地已准备。依赖事实体积与完整 JAR 分开保留，删除资源副本不删除约束证据。

不在当前聊天启动全站递归抓取或大型压测。默认先以少量明确的根和实际 26.3 环境验收，后台扩展关闭；验收后才按配置启用。后台并发起步 1，单根设置节点/边、每目标候选、总下载字节及截止时间上限，超过返回可续跑的 partial；不能因为开启一个开关就占满小内存服务器。已存在的事实与实体复用，不重复扣除下载预算。

### 查询及下载地址的准确性

无目标环境的按摘要查询只返回事实，不能凭一个模组文件确定所有玩家都通用的唯一依赖集合。闭包查询必须带目标环境/策略；返回根指纹、节点/边、逐项状态、未解决原因、选中文件摘要及整体闭合状态。客户端核对本地活动文件；指纹不一致或事实未齐仍使用同一检查/求解流程，不将远端候选当最终兼容认证。

下载返回内容身份和可续期的入口，不能把可能过期的 OSS 签名 URL 当永久事实。每次获取下载计划复核停供、权限、实体位置与当前空间/流量策略；提供源站按摘要定位入口及有出处的可用上游地址，标明有效期和可用性。实际下载还要验证大小/摘要。下架、权限变化、全上游失效、缺失实体、实际摘要变化必须使该项不可用或待重新准备，不能为了给出“完整清单”返回旧地址。

客户端可以提交/提供包内事实的线索，但第三方上报不能直接成为公共可信事实或 runtime_verified；服务端须取得对应完整字节重验摘要并自行解析。私有房间、未公开整合包、账号权限才能访问的文件和公开缓存分域处理，权限过滤沿依赖遍历和整个查询执行，不能通过依赖边泄漏私有节点。

目录观察、解析器、求解规则和运行验证各自带版本/时间。任务开始冻结观察批次及候选集合，途中出现新发布不会悄悄更换已经锁定的文件；规则撤销或停供立即使新下载计划重新核验，但不删除历史事实和验证记录。操作系统、CPU 架构、Java 及必要功能条件进入目标环境；没有相应环境实测不能宣称跨平台已验证。

### 规则复用与发布门槛

包内事实契约、版本方言、关系语义、闭包锁定及用户决定使用同一版本化规范和一致性样例；服务端事实解析只有 Collector，一个文件不会再被镜像/目录/管理 API 各解析一遍。客户端必须有离线原生实现，不能只调用 Bugg 服务。约束和求解算法实施时收敛为独立、无 UI/网络/存储副作用的可复用内核；服务端 worker 与原生安装器使用同一内核/版本，IO 仍各归原所有者，不让共享内核依赖启动器运行环境或私有数据库。不同实现暂未对齐的方言明确 unsupported，不能用简化比较冒充完整 Maven/Fabric 语义。

递归闭包先在受控依赖树验证后才开启生产扩展。相关用例包括链/菱形共享、循环可解与不可解、多父交集为空、旧新发布依赖增加/删除/变更、可选依赖已装/未装、内嵌提供者、多加载器、缺项目映射、下架与 URL 过期、停供/预算中断及重启续跑。另验源站缺失或离线时客户端可完成同一检查、自建包可选择原样继续或自动处理；最后仍以原生 26.3 自动安装并进入真实光影世界作为本次问题的最终验收。

## 客户端查询与本地兜底

增加公开只读、按摘要批量查询事实的契约，最多 100 个、限制响应大小，单独返回每项 hit/missing/pending/failed/unsupported。管理采集 API 继续鉴权，不直接开放管理接口，不把读取请求变成公开下载任务。响应必须带摘要、大小、事实 schema、解析器版本、状态和证据摘要；不信不匹配文件或未知 schema。

启动器先使用可信的本地事实缓存，再查当前源支持的事实能力。源不支持、超时、未命中或结果不完整时，下载到现有暂存区后读取 JAR 的有限元数据与已声明嵌套包；不完整解压，不执行 JAR，不启动 JVM 来解析。源站事实不能把其他来源的不同文件当作同一发布。

依赖发现先用平台 API 的项目/具体发布信息缩小候选；最终约束以具体文件事实为准。mod_id 与平台项目 ID 必须有可追溯映射，不能按相似名称自动安装。仅在接口未指定具体文件时，才在真实存在的兼容候选中选择满足所有约束的组合。作者固定依赖保留，不能静默改成最新；必要的修复例外单独记录精确文件、实例条件、原因、出处与实际验证，不能冒充原声明。

下载、摘要、续传、来源顺序、取消、任务明细和替换回滚继续复用 ResourceClient / HttpClient / GameOperations。完成整组暂存、核对已有活动模组和全部硬约束、取得必要的兼容性决定后再提交；失败不污染原实例。已禁用文件不作为活动提供者，不自动启用。解空间、候选数、解析字节和耗时必须有上限；无解或超限明确列出约束链，不无限重试或全站下载。整合包/房间的锁定文件不参与静默求解替换，遵守上面的原样安装契约。

## 声明之外的兼容规则

声明事实回答“作者写了什么”，不能保证真实运行。保留独立的已知问题/修复规则，按精确文件摘要和游戏、加载器构建匹配，附上游出处。禁止按模组名字永久写 if/else 补丁；不能靠切换 CF/MR 或换源绕过规则。规则可更新并持有已验证的本地快照；缺少可用依赖时给出冲突证据，不能安装另一个游戏版本的文件。
