## 参数与路径

CF 基址 `/v1/catalog/curseforge`，兼容公开反代 `/api/curseforge/v1`。GET `/categories` 使用 gameId=432，可选 classId；GET `/mods/search` 支持 gameId、classId、categoryId、categoryIds、gameVersion、gameVersions、modLoaderType、modLoaderTypes、gameVersionTypeId、authorId、primaryAuthorId、slug、searchFilter、sortField、sortOrder、index、pageSize。类别为官方 int32 ID，categoryIds 为 JSON 数组最多 10 项；游戏版本数组最多 4 项、加载器数组最多 5 项；数组覆盖单值的规则交给官方处理，不能自行改成求交。classId 对应模组 6、资源包 12、光影 6552、整合包 4471。分页 pageSize 1–50，index + pageSize <=10000。

MR 基址 `/v1/catalog/modrinth`，兼容公开反代 `/api/modrinth/v2`。GET `/tag/category`、`/tag/loader`、`/tag/game_version`，GET `/search` 保留 query、facets、index、offset、limit；facets 原样传递官方的组内 OR、组间 AND，不在源站重写分类，支持官方版本、加载器/内容标签、许可、环境等 facet。单页 1–100。

两平台同时提供启动器所需的项目详情、正文和版本只读路径；CF `/mods/{id}`、`/mods/{id}/description`、`/mods/{id}/files`、`/mods/{id}/files/{fileId}`；MR `/project/{id}`、`/project/{id}/version`、`/version/{id}`。版本列表保留官方版本/加载器筛选。游戏包下载、CF 批量指纹与批量 ID 查询不属于本次筛选网关，迁移时继续接既有镜像/分发服务，不能把元数据可查当作文件迁移已完成。

## 启动器行为与迁移步骤

1. 安装目标决定游戏版本及加载器；资源包/光影查询只传游戏版本。CF 使用 categoryId，MR 使用 categories facet；源站不翻译 ID，不混入本地项目名。
2. 服务端设置 TRANSLATION_CURSEFORGE_KEY，保持密钥仅在服务器；上游 URL 使用现有配置，禁止从旧平台读取生产密钥或数据库。
3. 合并 deploy/nginx.conf 的两个兼容反代，保持旧公开基址与启动器入口；先在测试域验证四种内容、分类、搜索、版本交集、分页与错误，再切 DNS/反代。旧站本轮仅补分类参数兼容，不进行部署。
4. 全量文件分发迁移另验许可、哈希、下载 URL、现有缓存/镜像回退；本次接口不执行文件下载、解压、翻译、索引或依赖求解。
5. 回滚只恢复反代到旧站，无 schema 迁移，无写入目录/包内事实的副作用。缓存与应用同寿命，配置/凭据随应用重启生效。
