# 多存储自动放置与主动缓存整理

日期：2026-11-11 至 2026-11-12

## 行为

存储列表顺序就是自动写入优先级。配置 `mode=auto` 后，普通镜像、资源缓存或房间缓存写入按本服务统一容量账本选择空间；每个空间将配额 95% 作为自动写入水位，并扣除在途预留、每日写入额度和本地磁盘保留空间。空间不可用、写入失败或容量不足时选择列表中的下一处；全部空间都暂不可写时任务保留并等待重试，不删除缓存、不把等待说成成功。固定目标继续使用显式空间。

`MirrorCloud` 维护跨存储位置索引。相同 SHA-256 已有任一已校验副本即可满足读取和准备任务，当前选择的目标空间变化不会重复下载或复制文件。普通缓存可以命中房间同步之前已存的副本。房间写入自动选择只考虑私有空间；云端对象仍沿用签名下载和上传完整性验证。多个本地目录若落在同一物理设备，容量预估按设备合并，避免把一个磁盘重复计算成多块空间。

云端下载按空间分别维护本月已授权分发量、预算和阈值。生成下载链接时在同一预算锁内先检查该对象完整大小；将会越过分流阈值的空间不会获得新下载授权，读取器继续寻找另一个已核验且未超阈值的副本。所有副本都达到阈值时，原下载流程走上游源映射或来源回退，不再向超额 OSS 下发新链接。后台空间行显示月用量/预算，达到阈值 80% 显示临近提示、达到分流线明确显示停止供流；容量页同时汇总预警。该数字是本站授权重定向的保守文件大小记账，不是云厂商账单的实际计费回执；外部直链后实际下载字节仍以各 OSS 账单为准。已下发而尚未过期的签名链接、公开桶直链无法由本服务撤回；绝对禁止云厂商继续计流量还需要私有桶及云端硬限额/权限控制，不能用本站重定向账本承诺账单绝不超额。

“主动准备资源”和“同步与分流”的重叠配置已经收为下载设置下单一“主动缓存”入口。游戏文件六类上限/平台、热门项目数量/类别/来源、更新周期和固定项目统一编辑及保存。执行进度、清单翻页、开始、排队、暂停和继续在同步任务页；重复开始不会创建第二个并行准备任务，暂停/排队状态落盘并可在服务重启后恢复。热门目录准备和游戏文件清单自动同步仍是两种已有任务，共用缓存位置和预算，并没有另起一套缓存。

容量组件显示每个空间的已用配额、自动写入可用量、预警和汇总预计空间。90% 已用显示预警，达到自动水位或写入空间不可用时告警/切换。云端可用量来自本服务已登记账本和配置预算，不能代表云服务商未知的桶内其他对象；上传阶段仍需本地暂存空间。

## 复现

在源站项目根目录使用当前项目虚拟环境执行 `PYTHONPATH='src;tests/platform' .venv/Scripts/python.exe -m unittest ...` 运行对应 `CloudCase`、`RoomCacheCase`、`MirrorCase` 和 `DirectRoomTests` 用例。前端从 `frontend` 执行对应 Vitest 文件及 `npm run build`。本地视觉验收脚本为 `frontend/tools/storage-pool-visual.mjs`；生产模式为只读浏览器检查，不保存配置、不发起资源准备。
