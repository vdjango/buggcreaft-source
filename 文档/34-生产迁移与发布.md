# 生产迁移与发布

用户于 2026-11-10 明确要求部署新版并补齐旧站迁移。本次允许在服务器内备份、接续旧站配置和数据；凭据不下载到工作区、不输出日志。历史文档中的“本次不迁生产”描述此前开发范围。

## 发布契约

- 翻译、账户、额度、目录继续由本仓库 `mc_translate` 唯一拥有；旧 SQLite、runtime-config、账户文件及镜像根原位接续，不复制一套业务实现、不双写。
- 发布前比较运行中的旧 Python 模块、符号和公开路由；本地旧目录不是线上唯一依据。源码与 Vue 构建打入独立版本目录，校验 SHA-256，保留旧目录供回滚。
- 主站复用现有 systemd 翻译服务，以 `bugg-source platform` 监督 hub、镜像、依赖 API、采集与索引 worker；停用旧独立镜像进程后才启动，保持单写。云凭据及房间缓存授权继续使用服务器现有文件。
- 18449 已被发布下载站占用。生产依赖 API 使用回环 18451，hub 18448、镜像 18450、可选 CPU 模型 18452。Nginx 由同一部署模板渲染端口；下载字节仍直达镜像，保留现有下载站与 CurseForge 下载网关。
- 事实与搜索使用独立 PostgreSQL 库，复用 Alembic；不得写入其他站点数据库。语义模型须校验已有模型清单，运行期不自动下载。
- 切换前冻结旧 writer，SQLite backup API 生成一致快照并执行 integrity_check；保存配置、服务、Nginx 和镜像账本。缓存文件保留原路径。失败时恢复旧服务/代理配置；新投影库不覆盖旧翻译库。
- 主站成功后更新第二镜像的代码，保留其配置、缓存、隧道和游戏节点。禁止同时运行两份镜像 writer。
- 发布验证覆盖译文读取、账户认证与新 API 会话互通、目录筛选、搜索、镜像 Range/校验、房间缓存路由、外部 HTTPS、页面与静态资源。付费模型只在明确预算内测试；缓存命中不冒充新翻译成功。

### CDN 缓存边界修复

最终匿名核对发现 translate.bugg.icu 的阿里 CDN 将已认证 `/api/v1/artifacts` 响应缓存 30 天并忽略查询参数；同一路径在源站和 mirror.bugg.icu 匿名均 401。已增加唯一 API HTTP 中间件为成功/401/422/404 统一发送 no-store，搜索路由复用，删除重复赋头；新增鉴权与禁止共享缓存回归并通过上述 Linux 全量测试。

旧 CDN 副本需要管理端目录刷新，修改源站不能删除既有边缘缓存。用户在 CDN 控制台完成 `/api/` 禁缓存与目录刷新后，两个主域匿名访问制品、任务、搜索状态、容量及制品详情均为 401/no-store，无 Age，404 同样 no-store。随后同一主域已登录请求为 200/no-store，退出再匿名仍为 401，确认不串用缓存。制品库、任务、搜索状态六张桌面/手机截图重新生成并查看，无溢出/JS 错误。依据：[阿里 CDN 缓存排查](https://www.alibabacloud.com/help/en/cdn/user-guide/cache-troubleshooting)、[刷新说明](https://www.alibabacloud.com/help/en/cdn/user-guide/refresh-and-prefetch-resources)。诊断和最终结果分别保留在 data/deployment-cdn-*.json。
