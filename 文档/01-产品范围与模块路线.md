# 产品范围与模块路线

## 平台为何放一起

同一个制品文件可以被资源目录展示、译文服务引用、依赖采集消费。共享项目/文件映射和内容摘要比三套数据互相对账更可靠。因此采用一个仓库、一个业务平台、一个生产 PostgreSQL；目录 API、采集 worker、译文 worker 分进程扩容。大文件由存储/CDN 交付，不经 Python API 转发。

模块边界不是多个网站：目录负责“有哪些候选”；采集负责“实际字节声明了什么”；翻译负责“如何用中文表达”；搜索负责“按词和意图找到哪些资源”；未来求解负责“当前实例选择什么”。联机同步只分发已确定清单，不参与猜测依赖。

## 功能拆解

| 编号 | 模块 | 最小功能 | 后续功能 |
| --- | --- | --- | --- |
| CAT-01 | 资源目录 | 对接旧平台项目/文件元数据 | 多源别名、增量更新、分页、下架 |
| ART-01 | 制品 | URL 流式落盘、SHA-256、预期哈希核验 | 对象存储、范围下载、策略化保留 |
| DEP-01 | 采集 | 解压元数据、身份、声明依赖、原始证据 | Quilt、旧 Forge 注解、规范化反查 |
| JOB-01 | 任务 | 持久队列、独立 worker、租约、取消、手动重试 | 调度优先级、按源限流、失败退避 |
| TR-01 | 译文 | 复用现有译文服务，不覆盖原名 | 增量翻译、术语、人工审核、中文检索 |
| SRCH-01..08 | 聚合搜索 | 多源目录、名字/别名、简介/正文原文及译文全文 | 中文分词、拼写近似、语义/相似资源、混合排名、筛选/片段；分阶段见第 22–24 号 |
| ADM-01 | 管理 | 提交、查看状态、依赖表、错误 | 分页筛选、证据下载、审核、统计 |
| SOL-01 | 求解 | 本轮只保留消费契约 | 单实例、MC+加载器+环境约束、可解释锁文件 |

## 本轮明确不包含

不采集互联网全部模组；不宣称支持所有历史加载器；不构建全局依赖图；不运行 JAR 验证游戏；不改启动器/P2P；不重写旧译文供应商；不创建虚构目录、好友、下载进度或成功结果。后续功能逐阶段验收，不把脚手架等同完整平台。
