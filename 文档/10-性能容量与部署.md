## 先按瓶颈分离

API 只做短事务/查询；同步 def 交给 FastAPI 线程池，不在 event loop 解压。worker 是独立进程，每进程同一时刻一个任务，通过增加进程扩容。CPU 解析受 Python GIL 的部分跨进程执行，下载主要受网络限制。JAR 分发未来交对象存储/CDN，Python 不承担大文件字节转发。

## 待验收指标（不是当前性能承诺）

固定 Linux 2 vCPU/4 GiB、PostgreSQL 同机、本地 SSD、10 万任务和制品快照：50 次/秒只读请求持续 10 分钟，查询 P95 <100 ms、P99 <300 ms；排队写入 P95 <100 ms。采集吞吐同时统计等待网络、哈希、解压、解析、数据库耗时及每 MiB CPU，不把慢上游算作框架处理时间。

进程 1/2/4 个分别测吞吐与 RSS；至少记录 10 MB/100 MB 制品、含 100 个内嵌 JAR、1 MiB 元数据和错误包。当前只做功能验收，尚未完成以上容量压测。

若数据库慢：先查慢 SQL、连接池/索引与查询模式。若网络慢：限流、缓存、直连来源/CDN。若 parser/解压占总 CPU >60%，且多进程和标准库优化仍无法满足目标，才评估 C++ 原生扫描器，通过版本化 JSON 契约替换 Collector 的解析实现；同一证据夹具必须输出一致。不能因“Python”三个字推断必须全量重写 C++。

## 初始部署清单

反向代理/HTTPS → Vue 静态文件及 /api → FastAPI；独立 worker；PostgreSQL 18；共享可写 data 卷。API 与 worker 必须使用同一 BUGG_DATABASE_URL、BUGG_DATA_DIR 和解析器构建版本。compose.yaml 当前仅提供本地 PostgreSQL，不是完整生产部署文件。前端 dist 需自行配置反向代理，FastAPI 暂不挂载静态页面。

上线前增加：非 root worker 容器、CPU/内存/PID/磁盘限额、只读代码、独立出口规则、数据库备份恢复、监控告警。指标包含队列长度、最老等待、租约回收、源错误率、哈希不一致、partial 比例、磁盘剩余和证据缺失。未完成这些不能声称生产全量就绪。

Python 精确依赖见 requirements.lock，前端见 package-lock.json。更新依赖要重新执行本次相关测试/构建；升级解析规则必须变更 PARSER_VERSION，保留旧快照。数据库镜像生产发布需固定版本/镜像摘要，当前 postgres:18 为开发主版本标签。

## 当前成本控制与局部测量

已实现强摘要完成态缓存/在途合并、parser 版本隔离、本地重验后重扫、按需优先、全局并发/排队/日下载/磁盘阈值。云上传独立 archive-worker，连接 5 秒/读取 30 秒、SDK 总尝试最多 3 次；归档容量和上传预算在 DB 原子预留，失败保守保留。细节见第 25、26 号。它们减少工作量，不构成上述生产容量验收。

tools/benchmark_cache.py 在隔离 SQLite 上提交同一强摘要 500 次，含首次仅 HTTP 1 次、解析 1 次、任务 1 条；缓存准入 P50 6.640 ms、P95 9.453 ms，预留 256 MiB。范围仅本机 Repository，不含 HTTP API/外网，不是线上 QPS。原始记录 data/benchmark-cache.json 被忽略；可用 --iterations 500 --output 复现。

制品目录标量查询+created_at/id 索引游标，最多取 limit+1 行，避免列表读完整 JSON 和深 OFFSET。路由懒加载；当前前端主 JS 约 167.42 kB、gzip 64.02 kB，六个页面独立分块。生产反向代理必须为 history 路由 fallback 到 index.html。全局 DB 闸门短事务是潜在准入瓶颈，上线需真实 PostgreSQL 压测后再优化，不能以 SQLite 单线程延迟外推吞吐。
