# 数据库与存储设计

2026-11-12 制品接线：迁移 0006 新增 `cached_artifacts(sha256 PK/FK,kind,public,job_id,updated_at)`，将公开发布与私有导入隔离；`artifacts.size` 在 PostgreSQL 扩为 BigInteger，SQLite 原整数可容纳。事实仍以 SHA-256/解析器版本唯一，重复通知不改旧快照。镜像自己的 SQLite 新增 `cache_facts(scope,digest PK,size,kind,state,accepted,attempts,next_at,error,parser_version)` 及分页对账游标；非归档在缓存账本记不适用，归档通知只入原持久采集队列。实际数据库迁移验收目前仅本地 SQLite；生产 PG 和部署尚未验收。就近采集、完整 JAR 暂存回收及递归闭包的后续存储设计见第 46 号，不能把当前基础表当整套已完成。

2026-11-12 镜像增量：同一镜像 SQLite 新增 `runtime_files(url PK,family,version,release_id,game,loaders,size,sha1,updated)`，索引 `(family,version)` 与 `sha1`；`runtime_objects(digest PK,sha1,purged)` 保留已清理问题对象的摘要身份。开库幂等创建，旧内部预览库缺 purged 时前向补列，不删账本。停供原因、准备请求与运行时间保存在 `runtime-distribution.json`；游戏配额仍在 settings.json 的 resource_prefetch.compatibility。

成都重装只恢复一致性数据库、设置、凭据与服务配置；本地资源实体按用户要求不备份，恢复后标为缺失/非本地，不按旧 ready 状态虚报存在。雨云位置和内容保留，本地资源由原准备任务补齐。恢复与验证见第 45 号。

## 本地与对象存储混合空间（2026-11-11）

扩展原 MirrorCloud / object_locations / cloud_jobs，增加 provider=local 的目录空间；每个目录独立配置容量、磁盘保留量及类别路由，与雨云/S3/七牛空间共用队列、摘要身份和副本释放规则。目录必须已经存在，不自动创建未挂载磁盘的挂载点。LocalStorage 只在既有 worker 的 to_thread 中执行有界复制、摘要与原子发布，不在 API 处理器复制文件。私有目录下载由原镜像进程校验绑定路径/过期时间的签名，使用 FileResponse 提供 Range/HEAD，不开放任意文件路径或代理 URL。所有本地空间共用现有 Egress 并发/预算入口；Nginx/系统出口预算独立于按字节预留的月度账本。

房间缓存策略归 RoomCache：adaptive 保留按来源状况选择补传，full 直接按 SHA-256 查重、缺失补传，已有实体不因文件改名重复上传；两种策略均保持授权、容量预留、租期、校验与清理。完整缓存不得用“请求已接收”冒充缓存完成。默认保持 adaptive，成都分发实例可配置 full。策略和存储归源站，启动器继续使用既有加速开关、逐文件计划与进度，不添加重复测速或客户端慢速回退规则。

> 2026-11-09 迁移更新：本页 PostgreSQL/Alembic 表属于依赖事实领域。迁入的 mc_translate.Store 另用 data/platform/translations.sqlite3，保留 aiosqlite/FTS5；镜像有自己根目录的配置、副本与来源账本。单个 hub 写平台库、单个镜像进程写其账本，不能把 PG URL 填给 TRANSLATION_DATABASE 或启动多个平台写入副本。平台 PG 化按目录/原文、译文/分段、任务/额度、身份/统计逐域导出、行数/摘要对账、冻结写入、导入及恢复演练后切换，不直接替换 SQL。平台资源以 provider/project_id/file_id/摘要关联 JAR，不按名称关联。备份分别覆盖平台一致性 SQLite 快照、镜像配置/账本、事实 PG、CAS 和外部凭据。此次未搬生产数据。

## 选型结论

生产 PostgreSQL 18 + SQLAlchemy 2 + psycopg 3 + Alembic；开发测试可用 SQLite，但不把 SQLite 的测试通过当作 PostgreSQL 多 worker 验收。依赖清单无需图数据库。版本区间保留原文，不能用 PostgreSQL 数值区间代替 Maven/Fabric 语义。JSONB 适合保存异构字段，但需要查询的 ID、状态、时间和外键单独建列。

## 存储、迁移与一致性

磁盘：`data/blobs/<sha256>.jar`；`data/evidence/<sha256>/...` 保存受限解压的原始元数据；`data/tmp/` 暂存。内嵌 JAR 同样保存并计算摘要。先持久化内容/证据，再事务提交结果；崩溃可遗留孤立对象，不会提交指向 .part 的成功结果。清理器以后按数据库引用+宽限期回收，当前不自动删除。

迁移用 `alembic upgrade head`；开发也执行同一迁移。生产不运行 `metadata.create_all()`。0001 初始三表，当前 0004 共十张业务表（不含 alembic_version）。先备份、停 worker、排空旧在途任务，再前向升级；0002 不虚构历史任务指纹或未保存的 SHA-512 映射，旧强摘要映射缺失时首次需重新核验。禁止删库重建升级。SQLite 仅单 worker，不能共享网络磁盘；PostgreSQL 使用 SKIP LOCKED 及 token 条件提交。

当前新增表：collection_keys（指纹主键→任务）、collection_gate（准入/领取短事务闸门）、download_budgets（UTC 日预留）、artifact_hashes（已核验摘要→制品）；archive_objects（空间+key 唯一归档队列）、archive_spaces（托管容量预留）、upload_budgets（空间+UTC 日上传预留）。0002 增加 Job 的 parser_version/priority/cache_hit/reservation_token 与状态/优先级/租约索引；0003 增加归档三表；0004 增加 scans(created_at,id) 游标索引。预算和失败容量保守不退款，详见第 25、26 号。

制品目录按 scans.created_at/id 倒序稳定游标，JOIN artifacts 仅读摘要、大小、状态、解析器版本、时间和 ID，每次最多 100 条；不读完整 result JSON、不 COUNT 全表、不依赖任务历史。详情按制品+解析器唯一索引取快照。单次保存先持久化本地文件，scan 与待归档对象在同一事务落库；云失败保留本地事实与文件。

## 备份、容量与扩容计划

上线前：PostgreSQL 每日逻辑备份 + WAL/PITR，目标 RPO 15 分钟/RTO 2 小时；每月在独立库恢复并核验随机 scan 证据哈希。文件存储开启版本或不可变备份，数据库备份单独不能恢复 JAR。上述是上线目标，当前未部署验证。

粗估：100 万制品 × 平均 5 MB ≈ 5 TB JAR；平均 20 KB 快照 ≈ 20 GB，关系投影/索引/WAL 另计，实测 P50/P95 替代假设。初期不分库分表；先连接池、正确索引、对象存储与独立 worker。Redis 只在缓存/限流或通知需要时加入，不能成为事实源。

0004 十张采集/归档业务表加 0005 六张搜索表，PG 当前共十六张（不含 alembic_version）；SQLite 的 0005 明确不创建搜索表。compose/CI 固定 pgvector 0.8.2 + PG18；真实 PG 已验证租约、跨 API 游标与撤回。模型基线 512 维，当前无 ANN；100 万项目×两语言×八块×512×float32 约 32.8 GB 原始向量，索引、正文、重建/WAL 另计，不能按小夹具推断规模性能。目录 SQLite 增加三张 search_* 导出表和触发器，只有 hub 写；不能把它共享给多个写节点。
