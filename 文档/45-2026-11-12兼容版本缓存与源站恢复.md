# 兼容版本缓存与成都源站恢复

本记录限定 2026-11-12 的加载器/核心缓存、成都重装恢复和存储修复，不代表历史全部产品要求均已完成。

## 后台操作

入口：[加载器与核心](https://mirror.bugg.icu/admin/mirror/runtimes)。支持 Fabric、Quilt、Forge、NeoForge 及 Iris、Sodium、Oculus、Embeddium。Sodium、Embeddium 是核心依赖，按模组类别分发规则处理。

“缓存规则”支持全部正式游戏版本、最近 N 个正式版本或指定版本，再设置每游戏每项目最新几个兼容发布，可逐游戏覆盖数量。热门设置仍决定准备哪些项目，两者共用兼容规则，没有第二份配额表单。

固定资源设为“自动跟随”时，同样使用这组游戏范围、每游戏数量及停供过滤，为该项目选取最新兼容发布；不会只缓存一个没有游戏范围判断的最新版。选了具体文件版本则保留为精确固定项，不随热度规则换版。同一发布明确支持多个游戏版本时只占一份存储，并分别计入各游戏版本名额；只按上游明确支持列表判断，不用范围端点猜中间版本。

例如 1.21.1、1.21.2、1.21.3 都设为 5，如果最新 5 个文件明确支持这三个游戏版本，只存 5 份文件。支持列表中缺 1.21.2 时，不由最小/最大版本推断其支持。先排除问题版本再计数，从最新向旧补足；可用版本不足时保留实际数量。同内容按摘要合并，不按名称猜测。

在目录标记问题版本并填写原因；未收录的也可在停供记录添加明确类型/版本。本站立即停供，随后后台清理登记的本地/云端副本并安排补位；正在使用或删除失败的对象延后重试。恢复后若文件已删除，则重新准备。新增加载器/核心的定期准备默认关闭，避免升级自动扩大缓存；原热门排行和固定项保留。原作业页继续显示实际运行与传输，不再建一套任务系统。

## 复用与边界

| 能力 | 唯一所有者 / 复用入口 |
| --- | --- |
| 游戏范围、数量和发布时间选择 | ResourcePrefetch.game_plan / compatible / compatible_releases |
| 发布身份、停供和摘要记录 | Mirror 持有的 RuntimeCatalog |
| 发现、准备和传输 | Inventory / Sources、原 Mirror 调度器与队列 |
| 跨空间命中、预算和删除 | MirrorCloud、原存储适配器 |
| 后台 | 原 Router、认证、mirrorWorkspace、共享抽屉与主题 |

目录的缓存响应每次应用当前停供策略。文件命中、回源、重定向及已登记摘要地址使用同一检查。已观测的官方版本 ID、SHA-1 和跨平台别名可关联；未知来源且未获得身份/摘要的文件不能凭空识别。本站不能撤销此前已发出的云签名链接，也不能控制玩家直接访问第三方。

清理每轮最多 5 个问题对象，复用传输锁，保留停供身份；删除后已知摘要仍拒绝提供。同摘要的房间同步副本也受停供影响，其他正常资源和雨云内容不在清理范围。恢复操作不能撤销已经发出的云删除，已删除内容重新获取。配置声明兼容不保证所有模组组合都能启动，明确问题通过版本标记处置。
