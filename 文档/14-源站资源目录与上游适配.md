# 源站资源目录与上游适配

## 定位与已有服务

原平台现已完整迁入本仓库。mc_translate.sources/metadata/store/api 继续拥有 Modrinth/CurseForge 项目、正文、版本候选和目录缓存，公开 /v1 保留；不依赖旧站运行，不读取其生产 SQLite。平台版本依赖和项目标题只作为上游信息，页面明确“未经包内扫描核验”，空依赖数组不显示为真实零依赖。

## 下一阶段事实联动与增强工作（未实现）

1. CatalogPort：分页项目/版本/文件 DTO；来源标识与 ID 保留，不用展示名作为唯一键。
2. 上游适配：Modrinth 版本文件、哈希、标签和下载地址；CurseForge 文件接口、下载许可/受限文件情况；本地平台已有适配器作为首个复用对象。API 给出的 dependencies 进入 source_hints 旁路，不能当 scan 事实。
3. 增量游标：按来源更新时间和稳定 ID 分页；水位只有整页提交成功才推进；不可下载/删除单独记录，不能标为零依赖。
4. 文件入队幂等：provider+file_id+observed_hash 形成键；新摘要新观测，不覆盖旧制品；文件无摘要时以 URL/观测时间追踪，下载后按 SHA-256 归并。
5. 限流：每源并发/令牌桶、429 Retry-After、失败退避；目录同步与采集队列分别控速，磁盘低水位暂停新的下载。
6. 来源政策：是否允许缓存/再分发单独保存。下载用于取证不自动代表能向其他用户公开分发；没有允许下载的文件记录状态，不绕过受限 URL。
7. 数据发布：仅有真实 scan 的文件可显示包内依赖；尚未采集显示 pending，解析异常显示 partial/failed。上游项目描述可展示和翻译，但不能被 parser 消费。
8. 聚合搜索输入：标题/简介之外收集允许索引的完整项目正文，保留 provider/ID、原文哈希、版本、许可和可见性；多源项目关联需要明确证据，不能按名字合并。目录/正文/译文更新与删除通过 outbox 或旧服务可对账的增量契约送往搜索，见第 22–24 号；不在玩家搜索请求内抓全站。

## 复用规则

路由/下载/CAS/哈希复用现有 ArtifactStore；持久任务复用 Repository；元数据规则只扩展 parsers。不得目录同步自己解压一次、翻译又解压一次、依赖模块再解压一次。新来源只提供候选 DTO，后续全部走同一采集管线。

目录现有 FTS5/trigram/短查询回退只覆盖名称/简介及其译文，正文可展示不等于正文可全文检索；多源聚合、语义、相似资源仍按第 22–24 号实现。任何网页字段均不得写入 declared_name/dependencies。
