## 观察、修改与复核

最初单页混放提交、任务、声明，已拆为六页。制品库无下载表单/运行统计；任务页无声明表/设置；新建页只有提交；设置只显示配置上限；运维只显示当前预留/计数。浏览器脚本同时断言这些业务边界。

连接成功后凭据表单折叠，保留短连接状态。窄屏菜单改两列分组，摘要/证据换行；依赖表保持可读列宽且在容器内横向滚动，并显示滑动提示。没有页面级横向溢出。看图发现详情/新建子页缺少菜单高亮，已修复并重新生成检查；常见 401/404 改中文展示，原始事实/约束保持不变。云 fixture 水印唯一，不会误报生产数据。

最后浏览器脚本生成 24 张图片，pageerror 为 0，全部页面实际打开并逐图核对；相关请求/会话/切页竞争另有 Vitest 测试。真实 PostgreSQL、多用户正式登录、雨云网络上传、长时间断线恢复和生产负载未在此验收，不能由截图或 Stubber 推断完成。

## 复现

先用隔离配置迁移并启动 API、Vite，导入可核验的真实 JAR。前端目录设置 BUGG_VISUAL_TOKEN 为该测试 API 管理令牌、BUGG_VISUAL_EDGE=1，然后 npm run visual。可用 BUGG_VISUAL_BASE_URL 指定 Vite 地址。令牌只从进程环境读取，截图输入为密码框，不写入清单。脚本假定测试库至少有一份已成功扫描的真实制品及对应任务；不面向生产管理站运行。
